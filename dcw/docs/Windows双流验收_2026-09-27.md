# Windows 相机双流验收

2026-09-27。用户授权在本项目建立 `dcw/`，完成本机 RGB-D 测试。已取得实际彩色与有效深度，60 秒双流通过；5 项离线数据语义测试通过。computer-use 目视核验实时两幅图像，点击关闭按钮后程序正常保存报告、释放设备。

## 实物与命名

- SDK 名称 **Gemini E**，SN **AY4A1520111**，固件 **RD3481**，USB2.0。
- VID **2BC5**，深度 PID **065C**，RGB PID **055C**。
- 官方 SDK/Viewer **v1.10.37**；深度驱动 **4.3.0.22**，Windows 发布 INF 为 `oem22.inf`。
- 深度帧尺度回读 **1.0 mm/原始计数**，不表示 1 mm 精度。

用户购买称为 DCW，询问 Gemini E 是否为别名。**查到的官方来源分别列出两者，尚未找到明确的别名/地区版本对应说明；不能仅凭识别名称判断机身/卖家型号，也不能直接等同所有规格。** 采集按实际 USB ID、固件和枚举模式匹配。

[官方 USB 映射固定提交](https://github.com/orbbec/OrbbecSDK/blob/7fa1485e751a779c4c845089c5b9721faaddd959/misc/scripts/99-obsensor-libusb.rules)列 DCW=`0659/0559`、Gemini E=`065C/055C`；SDK 支持表最低固件分别为 DCW 2460、Gemini E 3460。当前 RD3481 与 Gemini E 路径一致。[官方 SDK 页面](https://www.orbbec.com/developers/orbbec-sdk/)也分别列出 DaBai(DCW/DW) 与 Gemini E；机身标签/商业对应关系待核对。

本地证据：`evidence/sdk_probe_connected.json`、`usb_connected.json`、`drivers_connected.json`、`99-obsensor-libusb.rules`。

## 排障记录

1. 初次出现两个同名 RGB 节点，完整 RGB-D 枚举为空；用户确认只接一台，不能把节点数当成实物数。
2. 官方安装器签名验证通过；驱动文件经管理员 `pnputil /add-driver ... /install` 成功加入系统库。最初仍无深度匹配设备。用户拔插后，065C 深度设备出现，驱动正常绑定，SDK 枚举成功。
3. 最初深度帧全零，仅能算传输有帧。用户调整摆放后有效深度出现；没有为此改激光、曝光、LDP、固件或标定。
4. 首次计划 60 秒双流遇到 USB 设备脱离，应用在任一路 3 秒无新帧后退出，总时长 57.578 秒，记录为 failed；不计入稳定性通过。后续完成 15 秒与正式 60 秒验收。

SDK 初始化会打印不支持 frame sync 和 USB core type 警告；本程序未开启同步，实际独立采集成功。不据此声称支持硬件曝光同步。SDK 内部可能短暂重试，应用层不重新连接续采。

## 交付与边界

入口 `launch.cmd`，配套 `viewer.cmd` 和 `test_camera.cmd`。代码、SDK、Viewer、依赖、采集结果均在 `dcw/`。最终独立 Conda 运行时为 `.runtime/`（Python 3.11.16、NumPy 2.2.6、OpenCV 4.12.0.88），不依赖 OmniPicker 环境；初期用过的临时 venv 已停用。Windows 驱动必须进入系统 DriverStore，官方安装器还创建 `C:\Program Files\Orbbec\ASTRA`。

数据保留各流帧号、SDK 时间戳、主机单调接收时刻和深度尺度。原始深度零值不填补，统计占用有界内存，预览过期变暗。5 项离线测试覆盖深度单位/无效零、长度错误、RGB/BGR、MJPEG 尺寸和帧号/时间戳异常。

本轮未操作 E6/OmniPicker，未改固件、清标定、写 Flash、关闭 LDP。未验收测距精度、RGB 近焦、30 分钟稳定性、D2C、机器人时序同步或开发板接入。两图保持原始方向和各自分辨率；并排显示不代表已对齐、硬件同步或训练数据已适配。

最终独立 `.runtime` 另行复验 10 秒通过：RGB 292 帧/29.703 fps、深度 299 帧/30.034 fps，299 帧均含有效深度，零帧号缺口，清理正常；见 `evidence/independent_runtime_10s_report.json`。随后从独立运行时重新打开持续预览供用户查看。早期临时 `.venv/` 停用保留，正式入口只使用 `.runtime/`。
