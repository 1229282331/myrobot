# 旋转模式的奇异区退回

2026-10-10，v236。完整平台 Goal 仍暂停，本轮仅处理用户在旋转模式中无法退出奇异区的问题。修复已部署，正式网页完成一次低速实机退回；不外推所有奇异姿态或完整平台验收。

## 原因和行为

用户会话 `20261010-001944-d16f11a2` 的真实关节姿态对应官方模型 Jacobian 条件数约60.369，略超过当前普通档停止阈值60。原 MoveIt 2.12.4 在计算了离开方向的较高阈值后，最终仍用60停止所有方向。因此换旋转方向也无法退出，不能只靠改页面提示解决。

保留当前模式和已准备的会话。朝向更严重奇异位置的输入被阻止；松开后，改善条件数的可行旋转方向可以低速退回。不会要求一律切换关节模式，也不重启服务、不自动重放输入。

## 有边界的上游补丁

- 基于 MoveIt 固定提交 `1ade0e9dcf50dbbbc3a984b995c786cf12736235`，只改 `moveit_servo/src/utils/common.cpp` 的奇异方向处理；继续使用官方 IK、平滑器、碰撞及关节限位实现。
- 原接近停止阈值60保持。允许离开的范围沿原配置的 leaving band（30＋(60−30)×2＝90），超过60时最多采用请求速度25%。这只是局部可退回的范围，不代表机械臂可以安全穿越任意奇异点。
- 在原 Jacobian 上试算输入，确认预测姿态的条件数下降；再核对官方平滑器真正输出的候选，避免换向惯性让候选向更奇异的位置前进。
- 非有限数值、最小奇异值≤1e−10、条件数达到离开上限、或不能改善的方向仍阻止。严重奇异姿态可能需要关节方式退回，不能承诺所有笛卡尔方向均可执行。
- 控制器参数、ServoJ、TCP、碰撞、关节范围和断连／释放停止不变。诊断保存计算前后条件数和退回拒绝原因。

`prepare_directional_servo.py` 校验固定上游文件SHA，复制到独立构建目录并生成完整diff与来源文件，不修改上游子模块或安装的ROS包。CMake通过 `E6_DIRECTIONAL_SERVO_SOURCE` 选择该副本；原包和旧二进制保留以便回滚。
