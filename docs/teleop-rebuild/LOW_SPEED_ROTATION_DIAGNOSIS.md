## 已证明

1. 用户本次输入中的基座 Rx+ / Ry− 请求均为 **0.25°/s**。对应分段267/268发送21/22条目标；相邻目标旋转增量均为 **0.0125°**。发包间隔范围分别48.874–51.565 ms、48.919–51.459 ms。持续输入内部没有 Stop，发包不呈现约250 ms的中断，也未把小数截成零：官方 SDK 位姿保留六位小数。
2. 控制器原始反馈的 **全部六关节 QTarget** 连续保持不变约196–211 ms，再用约50 ms推进，约每250 ms重复一次。实际位置也呈阶梯状；Ry−段伴有明显的来回摆动。这一现象已存在于控制器回报的关节目标，不能单独归因为电机静摩擦，也不能归因为浏览器画面卡顿。
3. 1.25°/s的对照段263–266整体姿态曲线接近连续斜线；0.25°/s的两段明显分步。这个比较支持“小增量处理与低速跟随”方向，不能替代同起点、同方向的控制实验。
4. 选取的约148秒原始窗口共17983个1440字节反馈，帧头及有限数值检查通过、序号缺失0，Enable1/Error0/Collision0。无报警并不能证明顿挫正常或排除机械问题。
5. 整段事件快照有7055个发送和7055个确认事件、74个Stop及13个工作区边界事件；这只是计数，非本次对整会话逐命令合格宣告。其他段确有触边停止，不能将全部用户操作描述为无中止。此诊断的两段低速旋转不含触边或中途Stop。

## 因果边界

目前定位到 **连续笛卡尔目标 → 控制器关节目标及实际跟随** 之间出现台阶。ServoP在本机固件、当前t/aheadtime/gain、小角度增量下的内部插补、目标采用或死区处理，是下一项需要对照验证的假设。尚无证据认证某个固定最小步长、固件缺陷或机械故障，也没有把SDK六位格式化误认成瓶颈。

低倍速下每个目标的变化更小；若控制器暂时保持再集中推进，相同变化就会表现为等待—跳动，往复纠偏可能产生可听顿挫。这是与记录一致的解释，不是声学源定位。

下一项有效实验应为官方ServoP小增量最小对照，隔离正式页面与官方最小程序、保持同起点/同速度/同周期，核对QTarget的采用节拍。已有原记录足够，不先重复用户的异响动作。若证实此ServoP路线不能平滑处理所需低速，则按PLAN采用已建MoveIt Servo＋ServoJ路线作有界对照；不能只抬高最低速度、放宽故障条件或叠加重试宣布修复。
