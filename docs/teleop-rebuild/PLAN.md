## 1. 目标与完成标准

交付面向当前设备的完整本地遥操作工作台：手柄连接本 PC，PC 经无线连接 RDK X5，E6 网线直连 X5。用户能够通过键盘和手柄连续、平滑地操控机械臂与夹爪，同时查看真实相机画面、录制示教并处理连接异常。

允许重建界面、替换控制架构及部署 Linux／ROS 环境。保留历史证据和可回滚版本，不必保留现有实现。

| 项目 | 交付要求 |
|---|---|
| 操作能力 | 六自由度末端控制、关节控制、基座／工具坐标切换、连续夹爪控制 |
| 速度 | 普通档目标30 mm/s、10°/s；精细档25%；分级验证后开放 |
| 易用性 | 一键启动，设备状态清楚；选择输入并准备后即可操作，正常释放、切换和触及边界不反复报故障 |
| 界面与研究工作流 | 基于实际phosphobot应用完成统一、美观的正式工作台；常用遥操作、相机、示教、片段检查与恢复流程易发现、可连续完成。完成学术／工业平台调研、复用决策、视觉与任务流程验收，详见WORKBENCH_UX_PLAN.md |
| 流畅性 | 连续输入期间保持运动，不逐点等待机械臂完全静止，不积压历史输入 |
| 响应 | 正常无线条件下，输入至首次实际运动P95≤200 ms、P99≤400 ms |
| 视频 | RGB预览至少15 fps；采集到浏览器显示的延迟P95≤300 ms，注明测量方法和时钟误差 |
| 稳定性 | 最终版本完成30分钟综合测试，其中累计主动运动至少10分钟；正常操作不出现需重启服务才能恢复的软件锁死 |
| 可维护性 | 固定依赖版本、可追溯开源复用、自动化测试、结构化诊断、一键导出问题包、安装与回滚说明 |
| 数据 | 真实输入、发送动作、确认结果、实际反馈和图像可关联；成功、失败、中止记录均可检查 |

以上是验收目标，不能通过修改统计口径、降低受测速度或删除失败片段宣布达标。设备能力或物理故障阻塞时，保留已交付功能并明确报告，不能将残缺功能称为完整交付。

本轮不包含云端多用户、多机器人、模型训练、自主抓放和自动任务回放。

## 2. 技术路线与复用要求

采用[phosphobot完整应用](https://github.com/phospho-app/phosphobot)作为主工作台底座，直接保留和运行上游键盘／手柄控制页面、速度选择、输入显示、相机布局及相关应用组件。围绕E6添加适配层，允许维护有边界、可审查的fork。上游已有能力必须在本机运行验证，不能直接当作本套设备验收。

| 子系统 | 采用方式 |
|---|---|
| 工作台与输入 | 实际复用phosphobot页面和组件；补齐本项目映射、按住允许动作、状态提示及持续输入传输 |
| E6通信 | 使用固定版本Dobot官方SDK的协议、命令和反馈实现；仅对已复现上游缺陷维护必要补丁 |
| 笛卡尔连续控制 | 首选官方ServoP，由控制器处理运动学；先验证本机固件的连续跟随和停止语义 |
| 关节控制 | 官方ServoJ；MoveJog仅用于单轴诊断，不能冒充多轴连续遥操作 |
| 平滑处理 | 需要额外轨迹约束时使用成熟库，如Ruckig；不重新编写通用轨迹优化器 |
| 相机 | 复用已验证Orbbec SDK、UVC时间戳和采集配置；预览优先GStreamer／MediaMTX WebRTC |
| 数据 | 官方LeRobot数据接口；独立保存真实发送／确认事件，替换上游不符合本项目动作语义的记录路径 |

[官方SDK](https://github.com/Dobot-Arm/TCP-IP-Python-V4)列出E6及ServoP、ServoJ、MoveJog接口；具体固件行为仍需实测。

明确淘汰旧局部多项式运动学作为实机主控制依据。显示模型的误差只能影响模型健康状态，不能杀死原始反馈读取、停止确认或资源释放。

如果本机ServoP经官方示例最小复现和适配层对照，确实无法满足连续多轴控制，则转入唯一备选：MoveIt Servo＋官方E6模型／驱动适配＋ServoJ。先核对模型关节定义、坐标变换及控制器FK；禁止局部拟合或任意常量偏移掩盖模型问题。[MoveIt Servo说明](https://moveit.picknik.ai/main/doc/examples/realtime_servo/realtime_servo_tutorial.html)

每个核心模块列出上游地址、固定提交、实际使用路径、本地修改及原因。只引用论文、复制按键名称或读取几行Gamepad API，不算完成框架复用。

## 3. 控制行为、接口与交付步骤

### 控制与异常处理

- PC发送最新操作意图；X5本地执行连续控制、接收反馈和处理停止。视频、编码及写盘与控制执行分离。
- 保留一个实机控制所有者。网络恢复后丢弃旧输入，不重放、不追赶。
- 输入、设备反馈和图像分别维护新鲜度。不同进程／主机的单调时钟不直接相减。
- 操作状态简化为“未连接、可准备、可控制、暂挂、设备故障”；技术诊断放入展开区域。
- 松开允许动作键属于正常停止，保持会话；再次按下能继续。模式／坐标切换在松开且回中时完成。
- 工作区边界或不可达方向停止该方向并提示，允许向可行方向退回，避免整会话锁死。
- 短时延迟按新鲜度和未确认命令状态处理。丢弃过时周期；不能因单次超过目标周期永久锁止，也不能盲目补发未确认命令。
- 失焦、输入断连、控制失联或设备故障时停止。重连后回中并显式恢复，不自动续动。
- 原始反馈独立运行；模型错误、录制失败、预览解码失败不能终止反馈线程。
- 普通退出停止控制并释放本次资源，保持已有使能；停放、下使能和关机是独立流程。

必要接口只有三类：操作意图、实际设备状态、动作执行回执。明确单位、坐标系、序号、时间戳及有效性，区分请求目标、控制器接受目标和实际状态。不得通过多层重复租约和确认制造竞态。

### 实施顺序

1. 保存当前提交、未提交修改和必要证据，检查凭据后归档；创建`codex/teleop-platform-rebuild`。逻辑替换旧实现，不破坏Git历史。接管前确认旧控制进程停止并释放连接。
2. 隔离环境运行phosphobot原版模拟控制，验证页面、输入和构建，再添加E6适配。先交付可操作纵向链路，避免先开发大批诊断工具。
3. 从新实际姿态验证ServoP零增量、小幅连续运动、释放停止和重新操作。运动学问题不能阻断只读观测。
4. 接通正式网页→输入→无线→X5→E6→反馈／相机。自动测试经过该链路，不用独立直接关节指令代替网页验收。
5. 接通夹爪、视频和示教。真实反馈核对有效行程、反向跟随和到位。历史堵转不直接认定为正常端点；有证据才修正标定。夹爪问题独立呈现，不无理由使机械臂失效，不靠永久禁用夹爪完成目标。
6. 低速、小范围逐级提升至30 mm/s、10°/s。每档检查实际速度、方向、停止距离和附件余量；提供启动入口、说明、证据与可回滚发布。
7. 在核心链路稳定后完成研究平台调研和正式前端完善：整理工作流与信息架构，复用上游实际组件实施改版，使用真实设备状态与真实片段验收。可先以模拟或只读数据验证布局；交付前由代理通过最终界面代输入完成完整操作流程验收，用户实体输入体验留到交付后。只回归受界面改动影响的检查，不因纯视觉调整重复完整长时动作测试。

平台架构可配置更大工作区，但本轮实机测试不扩大已实际验证的局部空间；后续扩展属于另行验证事项，不是本轮交付前必须执行的动作。

## 4. 自主验证与工作纪律

### 实机闭环

- 输入及控制器实际反馈判断运动方向、幅度、速度和停止。
- 新相机画面及视觉运动检查可见环境、明显碰物和画面更新。
- 控制器模式、报警、真实夹爪回包与连接健康判断设备状态。

相机不能独立证明全部关节静止，也看不到所有肩肘、线缆及人员；透明物体深度缺失不是空间清空。沿用仍适用的现场事实，同一包络不逐段询问。仅在相机无法确认且决定下一步动作的事实缺失时合并提出一次必要问题，等待时继续软件工作。

### 验收用例

- 三轴正负、旋转、工具／基座、多轴、精细档、夹爪开合与释放保持。
- 连续100次开始／释放、20次模式／输入切换、10次断连／恢复；无意外续动或必须重启的锁死。
- 手柄未激活、下拉框焦点、文本编辑、失焦、页面关闭、第二标签页争抢、重连。
- 无线抖动、输入过期、E6断流、相机断流、控制进程退出、写盘失败；核对实际停止与恢复。
- 正常收到释放后X5停止请求P95≤50 ms；正常释放后的稳定收敛最大≤1秒（2026-10-07用户最终修订）。仍按原250ms各关节峰峰值≤0.01°窗口报告收敛时间，并报告停止距离与速度尾部，不把1秒解释为允许按原速度续动。断流及故障另计检测、停止时间与停止距离，符合受测空间；硬件急停不以普通松键的收敛测试替代。
- 成功、失败、中止各一段真实示教；核查动作标签、原始反馈、图像关联与异常保存。
- 交付前由代理代输入验证键盘、手柄映射及正式网页完整链路，包含连续输入、释放、模式／坐标切换、焦点、断连与恢复，并以真实控制器回读和相机作闭环证据。不能绕过映射直接发关节目标代替输入验收。
- 用户亲自操作实体键盘／手柄的体验验收留到交付后，不要求提前配合，也不因尚未进行而阻塞交付或Goal完成。报告区分自动信号、已有物理设备证据和交付后待体验项，不把模拟接收器断连称为实际拔插，不冒称代理亲手操作过手柄。
- 完成WORKBENCH_UX_PLAN.md中的调研、视觉、可用性、录制与数据检查流程验收；保留最终页面截图与走查结果。调试按钮、占位入口或漂亮截图不能代替可用工作流。
