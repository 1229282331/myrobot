# v77 相机中断恢复

2026-10-08。两次真实静止采集暂停后，在同一会话恢复画面，并经正式 phosphobot 键盘页重新准备、控制夹爪成功。相机进程退出后原始 E6 反馈与工作台保持存活。完整平台目标仍未完成，正常释放稳定上限仍为 1 秒，Stop 立即发。

## 实现与复用

保留原 Orbbec Camera.read、SDK 1.10.37 与已验证 UVC PtsClock；新增薄恢复适配。超过 500ms 采集间隔、已知旧 UVCH 接收时间或 PTS 不连续触发旧帧丢弃。只在带有效内核接收时间的新 RGB 到达后恢复，不让深度帧或未知时间戳证明 RGB 新鲜。每次中断建立新的 capture_epoch，复用原 PtsClock 重新展开，原 SDK/PTS 字段不改写。不识别的元数据结构错误继续报错。

源接收时间由同主机 CLOCK_MONOTONIC 与 perf_counter 的实测偏移换算，单独保存 source_received_perf_ns；SDK 等待返回时间继续保留。预览与健康判断采用真实源接收时间，不因重新读出旧图而刷新。深度无内核时间时明确使用 sdk_wait_return。未宣称曝光同步。

session_runner 对相机子进程退出单独记录 camera_unavailable，保留网关及反馈/停止所有者。网关退出仍结束会话。此处没有实现相机子进程退出后的重启入口，不能把隔离故障称为该类自动恢复。

## 真实证据

会话 `20261008-010059-da3cf301`，唯一相机进程 130914。两次仅对已核验归属的该进程 SIGSTOP 3 秒，在 finally SIGCONT；均在机械臂及夹爪静止时注入。

| 项目 | 第一次 | 录制中第二次 |
|---|---:|---:|
| SIGCONT 至新 RGB | 1089.177ms | 847.400ms |
| RGB 失效周期 | 73 | 66 |
| 暂停至显式准备的 CAN 保持回包 | 1895 | 10506 |
| 保持目标 raw | 109 | 96 |

所有失效周期控制暂停、夹爪保持 ready；上述期间 CAN 目标没有改变。两次恢复均从 RGB index 2 开始，以不同 epoch 明确分段。显式准备后第一轮夹爪闭合到 raw92，第二轮回传校验完成后张开到 raw112；全会话 7 组正式约 1 秒输入均到发送目标，释放后没有目标变更。

录制片段 `20261007T170635Z_a8a8f399` 因 RGB 过期中止，80.048秒/1588周期。1586条原 CAN 发回包含保持，仅19次目标字节改变；所有发回配对确认。2604张原图、9771条录制原反馈经自动回传、原字节 SHA 与尺寸校验，正式页面首尾采样可浏览。包 SHA256 为 `fc58d66076b21559436fa3a6731cf254a0829d8c0ff03fe03c9a9f46e45bdb50`，完整包留在 runtime，Git保存压缩原始事件、反馈、关联与清单。

704条无效动作关联原样保留，含2条无有效前置机械臂反馈、3条无前置RGB，19次变更目标中14条图像关联无效。源内核接收至 SDK 可用时间中位32.318ms；旧按20Hz采样时刻选图还增加了等待。仅离线候选分析改选动作前已从SDK收到的最新已存图，仍用100ms源年龄，无效数为183；尚未用于生产，更未改写旧704项。中断期间过期图本来就应无效，不能通过未来帧或放宽阈值消除。

之后在静止/已暂停/回传完成状态终止本会话相机进程，30次网页状态采样覆盖约6秒，反馈序号147195→147940，全程新鲜且连接正常，RGB失效、控制保持暂停、夹爪未误锁。此项证明故障隔离，不是相机进程重启或运动中制动验收。

全会话152231条已接纳SDK原帧均有效、无缺号、Mode5/Enable1/Error0/Collision0；21799 CAN 发21799回，state0为21664、state1为135，fault/state2/state3为0。E6运动/Stop/Enable发送均0，因此不把本次当作机械臂停止或速度复验。实际RGB均速约17.07fps、深度29.78fps，含两次中断，预览解码延迟还未完整验收。
