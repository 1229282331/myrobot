## 假设与改变

v177在0.5°/s下，首发约33ms，而首发后实际关节跨0.01°仍需约183ms。官方SDK只说明`t`为运行时间、aheadtime/gain类似D/P参数，不能假设其内部延迟。原ahead20/gain750对照未稳定改善，本轮不再盲调设备参数。

以新实际J6约−2.859°起步，保持原MoveIt2.12.4 C++适配、官方ServoJ(t=.1/ahead50/gain500)、20Hz及基准±0.35°约束，只比较1.0倍×精细25%=2.5°/s、正反各100ms的正式页面输入。名义速度×时长仍为0.25°，但它不是实际位移承诺。全程只有一次准备，没有重设基准或补偿回程。输入与目标均经原映射、无线、X5和官方设备SDK。

为支持局部路线内的短输入，原ControlStatus验收入口新增100/200ms单次选项；短输入禁用连续往返。原键盘handler、映射、租约、运动/停止代码和上游版本不变。前端75测试及正式构建通过。静止未准备期间发布新静态构建并刷新，源码、SHA和构建记录在`frontend-update/`；会话部署清单仍准确对应未改变的X5 Python源码。后端复用v178的532通过/6skip，不因这一前端验收选项重跑完整后端或长时实机。

## 下一项有效实验
