# 控制进程垃圾回收停顿

2026-10-08，v156–v157。用户认可低速旋转修复后，接续正式页面普通档验收。

## 假设与证据

v155普通Rx连续输入中断时，网关generation2垃圾回收耗时118.395171ms，collected/uncollectable均0。控制回调168.324251ms，其中record_control_events占123.220995ms。原始反馈接收间隔142.528671ms，但控制器时间仍相差8ms，序号250345→250346且未换代。本次反馈过期由网关进程停顿造成，不归因无线。原失败完整保留于sustained-interruption-v156及live-jazzy-v155。

## 改变

网关在任何设备连接或worker启动前导入模块、collect，然后用CPython官方gc.freeze冻结长期导入对象图。会话对象在此后创建，动态循环引用仍参与GC，引用计数、GC开关、阈值和控制保护不变。退出资源关闭后unfreeze。已有freeze所有者时拒绝重入。

这只排除已定位的导入图扫描开销，不保证操作系统、ROS、网络或所有动态对象均没有停顿。

## 结果

- X5隔离进程、不连接设备：同导入图各30轮全量GC。原策略82.674–84.790ms；冻结后0.296–0.330ms。每轮1000个新循环对象全部回收，退出freeze_count=0。完整样本与源码SHA在startup-gc-v156。
- 28项专项、434项完整后端通过，4项POSIX测试在Windows跳过；48项前端与正式构建通过。没有把跳过项写成通过。
- 正式v156影子12754官方反馈帧全部有效、缺号0，设备运动/Stop/CAN均0。12秒普通Rx候选完成，正常退出资源为空。运行中gen0最大1.459ms、gen1最大3.057ms，未发生gen2，不宣称本段验证了运行中gen2。
- v157实机Rx12.011秒、228ServoJ全部确认，中间无Stop，恒定段约10.0–10.8°/s；释放Stop发送1.425ms，250ms静止窗口起始788.647ms。Ry候选姿态触本次10°范围，停止后同会话低速退回，无重启；该组不是完整连续通过。后续数据仍在采集。
