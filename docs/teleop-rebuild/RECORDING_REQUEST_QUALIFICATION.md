# v204 录制请求结果提示

2026-10-09，基线8f983e6。修复v203正式网页首次开始录制时，请求到达X5后等待约1230 ms、因过期被拒绝而页面仍无提示的问题。

## 改动与行为

继续使用原 `IntentSession` 的序号、来源与250 ms新鲜度验证。`NativeExecutor` 为每个显式录制操作保留操作类型、序号、处理时间、受理状态与原因，并写入原始事件日志。拒绝原因沿现有 `recording.error` 到达上游Recorder的提示区域；后续中立输入不清除它，新的显式请求成功后清除。

录制器本身的写盘等故障仍优先显示。没有增加租约、自动重试、补执行、放宽输入期限、改变运动目标或改变准备状态。`accepted=true` 只表示请求交给记录器，不表示片段已经完成；原录制阶段与文件校验结果继续独立显示。

## 验证

- 同一1230 ms过期请求在旧8f983e6和新处理器对照：两者设备调用和录制调用均0、dropped均1；旧版无提示，新版有明确拒绝结果。
- 64项受影响测试通过；完整后端608通过、7平台跳过。包括keyboard/gamepad过期、后续中立输入、显式新请求、重复序号、不覆盖记录器真实错误，以及结束请求的拒绝／重新受理。
- PC-only正式phosphobot页面→原输入hook→PC代理→新网关处理器，使用内存时钟和记录器替身，首请求注入1230 ms过期。页面明确显示“本次录制请求未被接受”；随后显式新点击显示“录制中”且旧提示清除，最后结束。整个测试未调用设备start、没有SSH、E6、相机、CAN或真实片段；界面标注“离线替身 · 无设备连接”。
- 前端和正式build未修改，复用v202；新增结果使用现有UI字段，不为文案再跑实机长测。替身PC服务正常exit0、监听释放。

证据在 `evidence/record-request-v204/`：old-new-comparison.json、测试XML、三条正式页面录制请求、截图、执行fixture与源码SHA。此结果不代表秒级停顿根因已解决，也不产生新的实机运动资格。最后实机状态和资源以v203的退出审计为准。
