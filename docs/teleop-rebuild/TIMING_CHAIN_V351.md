# v351 控制更新周期与计算期限拆分

2026-10-20。遵循用户最新要求：人为计算预算可以适当放宽，以连续操控、换向和停止体验决定配置，不以维持旧 42 ms 数值为目标。

当前尚未发布新生产时序。六组带真实相机、3D 和状态负载的隔离完整链路比较已完成；55/70 ms 两组均通过运动时序项，将作为下一步资格验证候选，但其中一组发现 Stop 事件日志快照问题，完整资格仍未通过。测试执行器仅有合成设备，本轮未发送实机动作。

## 改动

`CppCycle` 将原来与 50 ms 名义步长绑定的请求期限拆为独立参数，默认仍为 callback 42 ms / request 50 ms。三组候选为 42/50、45/60、55/70 ms，名义积分步长、写口最小间隔均为 50 ms。

同一时刻仍只有一个计算请求，下一步需要前一个实际发送回执，不累积待发轨迹。请求期限不延长其原始反馈的 100 ms、输入的 250 ms 有效期。回包到达后仍重新核对释放、epoch、反馈 generation 和实际来源；传输余量不代替 native 计算预算。

较宽预算仅由本轮隔离 worker 使用。它绑定已验证的 `2271ac99…` native 哈希，要求资格标记，并逐个核对实际回显的 callback、retreat、geometry 参数。正常生产 worker 未启用这些候选值。几何、ACM、TCP、负载与设备参数未改。

## 验证与对照

- 专项 87 项通过，涵盖期限边界、过期原始反馈/输入、释放及会话变化、父链与禁止补发积压、快速计算仍保持 20 Hz。
- 全部后端 1,219 passed / 18 skipped；测试前后源码 manifest 相同。
- 隔离 worker 参数与 native 回显检查 21 项通过，错误/缺失的回显或二进制标记会拒绝。
- 三档正反顺序共六组，每组 36 秒 Tool 坐标联合平移旋转和重复换向；真实 Servo、IPC、NativeExecutor、官方 SDK 帧解析和双审计日志，合成反馈延迟 150 ms、回复延迟 33 ms。真实相机/3D 通过不可 Prepare 的 shadow 平台提供负载。

重点读取：暂停及拒绝原因、计算及往返时间、同 epoch 发送间隔、写口原反馈/输入年龄、释放到 Stop 发送、换向到有效反向指令。换向指标包含已有 0.2 秒输入柔化，Stop 指标不等同于机械臂实际制动时间。暂停会使后续轨迹分化，因此它不是固定目标的纯计算基准；固定请求比较见 v350。

## 完成结果

每档两次，共 72 秒操作。三档合计 3,227 次合成写入：

| callback / request | 合成写入 | 暂停 | 原因 |
|---|---:|---:|---|
| 42 / 50 ms | 1,038 | 9 | 9 次 callback 超时 |
| 45 / 60 ms | 1,062 | 8 | 6 次 callback 超时、1 次模型碰撞边界、1 次计算流中断 |
| 55 / 70 ms | 1,127 | 0 | 两组均无拒绝、过期写、父链跳失或跟随停止 |

55/70 ms 两组 callback 最大 47.238 / 51.210 ms，往返最大 50.834 / 55.575 ms。它们合计 6 个活动 callback 超过旧 42 ms，2 次往返超过旧 50 ms；这些计算完整结束后，新的来源与写口校验仍通过。

该档同 epoch 发送间隔中位 56.981 / 57.096 ms，P95 69.148 / 68.774 ms，最大 94.408 / 88.589 ms；没有补发突发，也没有严格达到每 50 ms 一次。原 42 ms 两组中位 58.563 / 58.914 ms。比较没有显示放宽导致总体发送变慢，但个别周期长延迟仍需保留。

55/70 ms 写口原反馈年龄最大 85.753 / 89.240 ms；输入年龄最大 99.803 / 93.154 ms，均未改原期限。12 次中立释放到合成 Stop 发送为 0.638–3.068 ms；这不是机械臂真实制动时间。有效反向指令出现中位约 434 / 415 ms，包含原有 0.2 s 双级输入柔化，不把它描述为零延迟。

45 ms 第二组第 573 条活动回调出现 **305.483 ms** 墙钟长延迟，其中主线程 CPU 22.195 ms；退离 sample 等待约 285.768 ms、自身 CPU 3.050 ms，无缺页。原始完整回包保存在 `loaded/long-tail-573.json`。此时 150 ms 计算流监护已触发停止，迟到结果没有写入。它支持继续检查工作线程等待/调度，尚不能确定具体根因，也不能认为放宽到 55 ms 就消除了所有长尾。

独立原 MoveIt/FCL 检查 19,222 条路径 / 1,249,430 点，其中 19,206 条接受路径未发现碰撞样本。45 ms 第一组第 716 条被拒路径检出 5 个碰撞样本，说明该次是实际模型边界，不能计作人为超时。此核对属于合成路径采样，不是实机连续运动证明。

六组 worker 正常结束、无诊断丢失，双审计事件计数全部相同；四组 journal 逐字节一致，42-a 和 55-a 各有一条 `stop_requested.receipt` 的确认字段不同。总实验退出码 1 和 `analysis.passed=false` 原样保留；`profile-qualification.json` 区分 55/70 ms 通过运动时序项、日志一致性未通过。225 个文件、57,163,338 字节压缩包与各成员 SHA 已验证；远端重复大文本在双端原包验证后归档，原失败资料可恢复。

日志问题已定位到 gateway 将可变 `Pending.event` 引用直接放入事件队列。两个审计线程排空时间不同，33 ms 后收到 Stop 回包时，旧请求记录的 acknowledged/accepted/reply/reply_ns 被改写。正式源码已改为请求时 `dict(...)` 快照，回包结果仍由单独 `stop_result` 记录；没有改变设备发送或 Stop 行为。新延迟回包/超时/结果记录回归及审计相关测试 9 项通过。该修复发生在六组负载测试之后，未部署，也尚未重做板端录制验证；原两条不同记录完整保留于 `journal-differences.json`。

停止时序分析初版误将“已经因暂停发过 Stop 后的中立包”关联到下一段 Stop，产生数秒假延迟；初版保留为 `timing-analysis-initial.json`，修正后的统计明确区分 already_stopped，全部释放均有对应停止或已停止证据。
