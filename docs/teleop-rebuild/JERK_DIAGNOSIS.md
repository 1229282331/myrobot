# v233 用户手动控制不平滑：只读诊断

2026-10-09。用户在v232操作后报告“卡卡的、不丝滑”。本轮只分析既有记录，不修改生产参数，不发运动、Stop、Enable或CAN，不重启服务。完整Goal保持暂停。

## 结论

当前链路的连续跟随质量尚未达到可称为流畅交付的标准。存在两项可复现于日志的软件问题：局部平移边界频繁中断操作；求解器与发送器的独立节拍导致下发目标跨步和速度不均。不能继续用通过单元测试、接口可用或命令已确认代替真实流畅性验收。

### 手柄平移边界

捕获段包含键盘旋转1286个ServoJ、手柄平移1847个ServoJ。39个`workspace_blocked`均出现在手柄平移，均为仍保留的TCP位置半径50mm界限；绝对关节范围检查均通过。60个Stop包含正常释放等，37个Stop与位置越界事件相邻100ms内。不能把60次全部算作故障Stop，也不能把39次称为旋转角度限位。

v232去掉的是相对姿态／关节10°范围，50mm平移球仍明确保留。边界用整机Stop来处理手柄连续方向输入会造成可感知中断；需要在授权工作区内改善方向限制／退回行为，而不是继续增加锁止和重启条件。本轮未擅自取消平移工作区。

### 连续旋转目标节奏

以同一X5单调时钟统计，同一MoveIt输入epoch内的3073个ServoJ发送间隔：中位56.589ms、P95 64.458ms、P99 69.837ms、最大80.487ms，原设计周期50ms。60个epoch之间的主动停止时间不参与这个分布。期间累计跳过415个求解器候选ID；同一epoch内没有中性计算，主要表现为下发的候选ID从递增1变为递增2。

例：epoch31，键盘恒定基座Rx=2°/s，7.112秒／124个ServoJ，段内没有Stop。剔除首末0.5秒后，105个相邻下发目标中，90次前进一个求解器步，15次前进两个步；角度增量分别约0.1°与0.2°。按真实发送间隔计算的目标角速度中位1.720°/s、P95 3.430°/s。原SDK位姿用8帧约64ms差分估计，实际角速度中位1.751°/s、P95 2.640°/s、P99 2.914°/s。该数值是差分速度估计，不是声学测量或驱动器瞬时速度认证。该段候选状态0有60个、状态1有64个，奇异减速也存在，但不能解释相邻目标一／两步的交替。

代码对应：`CppCycle.request()`以自身当前时间+50ms安排计算，并沿上次平滑候选积分；`NativeExecutor._moveit_step()`以最后一次发送+50ms限制消费；`MoveItBridge.take()`只消费最新候选。两个独立节拍没有同一发送时刻的轨迹采样约定。发送稍慢会丢过中间候选，下一目标累积两次积分，形成不均匀步幅。20Hz本身不等于必然卡顿，问题是目标时间与执行时间不一致；不能仅提高频率或放宽保护冒充修复。

## 排除与限度

- 3133个ServoJ全部取得接受回包；ACK中位12.111ms、P99 21.835ms、最大28.883ms。
- PC转发8192条样本，中位0.111ms、P99 0.279ms、最大0.632ms，全部sent。该统计不包含PC→X5无线传输，不据此宣称无线零抖动。
- 代表性持续段求解往返中位约3.1–3.4ms，无求解超期拒绝；不能把卡顿统一归为IK算不动。
- 94095个原SDK反馈有效，设备Error与Collision均0。读取时已因`page_blur`暂挂且静止。无报警不等于运动已平滑。
- 当前采集是运行会话的有界文件前缀，事件和raw文件分别取前缀，结束时刻略有差异；不是已封存完整会话，不与更晚用户操作混称。
