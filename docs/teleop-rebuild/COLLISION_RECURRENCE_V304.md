# v304 重复碰撞：J5 跟随异常与重置跳变

当前保持设备保护，未再次清错、使能、改参数或发送运动。生产软件未修改；完整 Goal 仍暂停。

## 已确认的证据

- 用户确认：本次没有接触或线缆拉扯，J5 出现突然抖动。
- 本次 session `20261019-030318-54e30db2` 的 315 条 ServoJ 均获确认；报警窗口 3043 个原始 SDK 帧序号连续。首个碰撞帧之后没有发送新的 ServoJ。
- 本次 J5 目标平滑下降到约 78.43°，实际角度停在约 85.21°，最大差 6.798°。其他关节同窗最大差小于 0.46°。
- 松手 Stop 后，下一段目标从最后发送的 78.474711° 重置为 85.209108°，相差 6.734397°；约 175 ms 后出现 CollisionState=1。J5 在报警前 1 秒的峰峰值 4.276°。
- 前一次 session `20261019-025821-fce18f14` 同样出现 J5 跟随偏差，最大 7.666°。200 条 ServoJ 均获确认，3039 个原始 SDK 帧连续，报警后没有继续发送 ServoJ。
- 前一次连续负 Rz 输入 epoch 15 内，J5 指令从 77.642014° 跳到 85.504978°，间隔 72.241 ms、跳变 7.862964°，中间没有 Stop。重置前 `official_solver_blocked` 的明确原因是 `sweep_travel_limit`（41.526 mm），不是计算超时。
- CppCycle 将拒绝设为 `reset_required`，随后在用户仍保持输入时自行进行一次 inactive 重置，再恢复 active。最终 status=0 覆盖先前 status=5，网关未记录到方向停止。原始时序和协议级复现均支持这个软件缺陷。

## 尚不能确定的部分

J5 起初为何停止跟随仍不清楚。反复在约 85°附近停滞并出现电流变化，需要区分驱动/机构、负载补偿及未建模的自接触；用户没有观察到外部接触，不等于已排除所有原因。SDK 电流和目标字段按原值保存，未将电流解释成已知力矩上限或证明过载。几何模型允许路径不代表关节实际能正常跟踪，也不证明物理环境无碰撞。

## 软件修复应覆盖的两层

1. 持续跟随偏差/无进展应停止并保留故障依据，不能只检查模型可达和几何无碰撞；恢复准备时也必须核对残留目标与实际状态。
2. 求解拒绝必须可靠交付给执行端，重置不能在持续输入期间悄悄恢复并产生目标跳变。指令连续性需要在实际发送边界检查，不能仅验证新候选相对于新的平滑器起点。

本轮完成诊断和无设备 IO 的故障复现，没有发布修复或进行试动；不能标记为解决。现有碰撞阈值、模型/ACM、TCP、负载和速度保持原值。
