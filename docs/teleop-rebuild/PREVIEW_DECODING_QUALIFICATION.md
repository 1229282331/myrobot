# 预览解码与片段浏览对照 v144–v150

2026-10-08。本轮只有 shadow；没有实机运动或夹爪验收。完整平台 Goal 仍未完成。

## 结论

当前 PC 内置浏览器中，VP8 比原 H.264 预览明显改善。两者复用同一相机采集、640×360/20 Hz 预览、900 kbit/s目标、FFmpeg、SSH媒体连接与固定 MediaMTX/WHEP reader。v150约165秒、808个像素测时样本：P95区间194.731–231.648 ms，显示帧率中位19.978 fps，无接收丢包、播放freeze0。首个启动窗口11.351 fps，81个窗口中1个低于15；慢窗口未删除，不能称每个窗口全通过。它是后续运动中验证的候选，不是30分钟最终资格。

前端修复了实际问题：历史列表展开会把视频推到约y=2999、使浏览器不再呈现视频。现在复用上游Radix/shadcn Dialog并限制列表滚动；视频布局不移动，原图、采样和关联可浏览。打开时停止并屏蔽输入；关闭后回中、显式准备，不自动续动。仍采样手柄按键边沿，跨弹窗保持的A/Start不被当作新按下。已按下的键盘键直到keyup才解除回中要求。

接收统计是标准WebRTC计数器，`totalDecodeTime`并不是另行测得的CPU执行耗时。无丢包指本段浏览器接收统计，不能证明所有网络路径始终无延迟。H.264在v146后段也曾恢复，所以不声称硬件解码器或驱动的物理根因已经认证。

## 测量、源码与复用

- 同一图像像素QR保留X5来源接收时间、epoch、frame ID；浏览器使用expectedDisplayTime及四时间戳时钟偏移区间。包括源时间量化与漂移预算，非曝光同步或屏幕光子时延。每阶段/全段均保留原窗口和失败样本。
- 正式页面、Dialog、SWR、速度/输入组件继续来自固定phosphobot `a5de051197c879e3c685d1362f649ce54ee47a3c`。`frontend/EpisodeBrowser.tsx`调用上游`components/ui/dialog.tsx`，没有自写模态框框架。
- MediaMTX固定版本及reader未改；React包装仅在`measure=1`读标准视频receiver统计。只保存视频数字计数器、codec和可选decoder名称，不保存ICE候选地址。没有测量配置时不轮询统计。
- `camera_service.preview_command`复用X5已安装FFmpeg/libx264/libvpx。VP8使用realtime、cpu-used8、lag-in-frames0、auto-alt-ref0；原H.264命令参数保持。`preview_codec`在启动时固定并与远端回读核对，原分辨率媒体/SDK/反馈/控制执行未换实现。
- 构建源文件与静态资源SHA：`evidence/video-diagnostics-v150/served-build.json`、`frontend-source.zip`。各X5会话实际源码/SHA、配置和日志见`live-jazzy-v144`至`v150/session`。
