# 正式输入传输分段诊断（v192/v193）

2026-10-09。基线2d6f162（控制生产源码仍ee82f9e）。本轮只做正式phosphobot页面的影子测试，没有实机位移、Stop、Enable或CAN发送；不能作为新速度或停止资格。用户限制的旧局部路线、线缆扫掠和禁止累计漂移要求保持。

## 假设与改变

v190的浏览器正反输入时长基本平衡，X5取出时已出现净积分偏差。本轮仅添加PC透明WebSocket转发的有界内存诊断：收到、开始发送、发送返回三个PC时钟点；保留连接ID、序号、浏览器采样时刻、字节数，不保留任意输入文本。8192条环形队列明确报告覆盖数，不在控制路径写盘、不改输入字节、不新增租约/确认/补发。`/e6/diagnostics/input-relay`供本地取证；发送返回不当作设备确认。

X5原`input_processed`记录增加已有连接ID，用于消除跨连接序号歧义。运动计算、周期、发送、停止、新鲜度与设备参数均未改。部署后发现诊断元数据中超大整数可能使`isfinite`溢出的边界，离线修正为先范围检查；正常报文路径不变，修正没有新实机资格。

43项专项通过：转发原字节/顺序、发送失败及取消不重试、坏元数据/超大整数不能中断转发、环形上限、正式拒绝路径与诊断端点、释放竞态、跨主机任意时钟偏移下积分分析不变、缺失关联不补造。未改前端、IK、媒体与记录器，不重复其长测；既有580后端/7skip和v183前端77项/build明确为依赖复用。

## 正式页面结果

v192会话`20261009-105924-77ba0e68`：Z正向起始与反向起始各一次、30mm/s名义输入、每向0.5秒、首尾半周期。9mm虚拟计算范围触边两次；第一组在3.44秒提前释放，不能称完整六轮。第二组完整发出13相位，但末段也有虚拟边界。原结果全部保留。PC接收至发送P95约0.19/0.20ms、最大0.60ms；两组主要净积分变化均位于PC发送与X5取出之间。

v193会话`20261009-110541-ce719774`仅将**shadow计算范围**改为50mm/10°/关节10°，避免静止实机和虚拟目标触边截断信号。正式页面同样两组、每组133个活动输入，13相位均完整，无workspace_blocked。没有扩大实机可走空间，此配置不能用于后续live。

## X5本地入口抓包

使用tcpdump采集X5 loopback的8776端口150秒，捕获从SSH解密后到网关socket的明文WebSocket。使用dpkt按TCP序号重组、固定环境官方`websockets.frames.Frame.parse`解码，再逐字段比对原输入对象。6734包，内核丢包0，重组缺字节/冲突0；2136个输入精确匹配。时钟配对区间宽0.015958ms，附带1微秒PCAP量化；假设窗口内无未观测的系统时钟跳变。

X5 loopback到应用取出：全输入P95上界4.973ms、P99 8.548ms、最大19.931ms。第一组活动段P95上界7.539ms。该组净积分在loopback入口已经为−3.351mm，应用取出为−2.417mm；PC发送约+0.006mm。因此主要偏差已经出现在**PC发送之后、X5 loopback之前**，残余包含PC本地隧道线程、Paramiko/SSH、无线及X5 sshd；尚不能独断归因某一层。

捕获结束时第二组尚未释放，仅76个活动输入被线侧覆盖。最初分析器因此拒绝整份报告；已改为明确列出这组`incomplete_active_group`，不计算它的完整线侧净积分，第一组完整证据保留。应用侧第二组完整133活动输入独立存在，不能假称它也有完整抓包覆盖。没有为此重跑实机或第三组测试。

PCAP原文件本地保留且Git忽略；manifest与SHA、解析器、逐条匹配和PC环形快照归档。原始全会话SDK及事件全部归档，没有新episode或伪造动作数据。
