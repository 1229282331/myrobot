用户希望将平移的柔和起步扩展到旋转。核查现有实现和当前 v258 会话，`IntentRamp` 已同时处理三路线速度、三路角速度和六路关节速度；正式网页旋转映射进入 `angular_rad_s`，与平移在同一个 X5 `CppCycle`、进入官方 IK 之前滤波。网关和实际 C++ 模型返回的 `input_ramp_time_constant_s` 均为 0.2 秒，未重复叠加滤波或修改运行参数。

当前保留的先前用户旋转候选 `10406`（输入序号 `7047`）请求基座 Rz −8°/s，其记录包含 `input_ramp` 原始输入、前后状态和有效角速度。按独立的两级指数解重算，最大状态误差小于 1e-14。该证据证明实际运行链路对旋转输入执行了滤波，不等于本轮重新发送了实机运动，也不能由候选角速度推断实际关节冲击已完全消除。

新增 12 项旋转请求边界测试：Rx/Ry/Rz 正负方向、基座/工具坐标，检查渐进起步、单轴方向及零线速度、平滑换向、周期内释放立即清除滤波状态、再次操作从零起步。连同已有输入、网关和停止回归，共 136 项通过。测试中的求解器回复为替身，仅验证生产输入处理与求解请求，不冒充新的官方求解器或实机运动验收。

当前输入响应维持：50 ms 达设定速度约 2.65%，200 ms 为 26.4%，500 ms 为 71.3%，1 s 为 96.0%；正常持续输入的速度上限不变。释放、失焦、过期和故障仍走原停止路径，不等待输入滤波慢慢归零。停止指令发出不代表机械臂瞬时静止。

## v252 更新：渐进起步与换向（2026-10-12）

用户确认 v251 有改善，希望起步更柔和。本轮已发布 **X5 端、进入 MoveIt IK 之前的临界阻尼速度输入滤波**。v251 运行会话已正常退出；当前是 `20261012-022734-8156037a / exec44629`，入口 `output/soft_ramp_operator_252.py operator`，退出文件 `output/soft_ramp_operator_252_operator.stop`。下文 v251 的运行会话为历史。

实际链路为：原网页输入 → 原网关授权／最新输入 → `CppCycle` 输入滤波 → 原工作区减速 → 原官方 MoveIt Servo／关节加速度限制 → 原 ServoJ。没有替换运动学或控制器协议。`intent_ramp.py` 调用现有 SciPy 1.11.4 `signal.cont2discrete(method='zoh')`，将标准 `H(s)=1/(0.2s+1)^2` 两级一阶滤波器离散化。12 个速度通道共用相同系数；零线速度的旋转请求不会因滤波产生线速度。正的单位增益脉冲响应使速度保持在历史有效输入的凸包中，不像独立关节轨迹滤波那样改变关节之间的路径关系。

- 持续阶跃输入：50 ms 为选定速度的 2.65%，200 ms 为 26.4%，500 ms 为 71.3%，1 s 为 96.0%。输入加速度先小、逐步增加再减小，不再直接跳到加速度上限。
- 最高请求速度仍 30 mm/s、10°/s，关节速度上限 30°/s、加速度上限 30°/s²。该滤波不是电机 jerk 约束，不宣称任意奇异区或限位附近的实际关节 jerk 连续。
- 带输入换向会平滑过零；**释放、过期、故障仍走原立即 Stop**。释放／中立／新 epoch／反馈重连／计算拒绝清除输入滤波状态，旧输入不重放。恢复后从零起步。
- 以每个真实求解请求推进一个 50 ms 步长，不按落后墙钟时间补算。工作区限制位于滤波之后，不能由残留滤波值突破边界。
- 记录同时保留原始意图、滤波前后状态及最终有效意图；审计脚本独立按指数解重算，验证输入和父状态关联。协议和原有字段保留。

## 实际记录证明了什么

来源为 R4 TCP / 新负载 operator `20261012-014040-e0e92433`。快照覆盖约 892 秒、108744 个有效 1440 字节反馈，源序号缺口 0，碰撞／错误／失能帧均为 0。3521 个 ServoJ 发送与确认逐项按 sent_ns 对应，无未确认；有 60 个活动起步和 60 个停止结果。它们来自用户键盘操作，不是代理自动实机测试。

J5 实际角度与控制器内部 QTarget 的最大差值为 **1.033329°**，P95 0.224177°、P99 0.447684°。这是包含静止段的整段描述统计，不是仅活动时的性能验收。本次没有复现 v247 的约 8.2–8.4° 失跟随，也没有新的碰撞置位；不能把用户看到的所有大角度运动都判成无指令下坠，亦不能用这一次无报警否定其体感或宣布旧故障已解决。

最相关的一次：epoch71，基座 Rx 正向输入 **8°/s**。J5 首个 50 ms 规划周期从零速到 **5.271581°/s**，规划平均加速度 **105.431628°/s²**；约 **258.445 ms** 后出现上述 1.033329° 最大跟随误差。两者时间相关，支持检查起步瞬态，不能单凭相关性判定惯性是唯一根因。该首帧的 J3 达到原 120°/s² 上限。

启动样本（60 次）J5 规划加速度绝对值 P50/P95/max 为 53.899 / 101.684 / 105.432°/s²。最大实际角度差使用原始 QActual 与控制器 QTarget；“发送目标领先量”是另外一个量，不能混用来声称失跟随。

原始峰值窗口仍回读 Load=0.553 kg，CenterXYZ=(0,−14,46) mm。配置没有退回旧负载。SDK `QDActual/QDDTarget` 的噪声和单位不用于本结论；规划加速度由同一官方求解器的 `(target_velocity − seed_velocity) / 0.05` 得出，不冒称电机实测加速度或力矩。

## 配置问题与修改

前端倍率仅缩放请求速度；普通档原固定关节规划加速度为 120°/s²。因此低倍率可能在一个周期内达到其较低目标速度，并不自然形成柔和斜坡。

本次只把 `motion_profiles.py` 中 normal 的关节规划加速度从 **120 改为 30°/s²**，继续使用已固定 MoveIt 的 `AccelerationLimitedPlugin` 及已有数值修补。不新增轨迹实现、不修改 IK、ServoJ、输入租约、停止、碰撞、工作区或方向限制。

- 最高请求速度保持 30 mm/s、10°/s，精细 25%；求解器关节速度上限仍 30°/s。
- 起步和带输入换向需要更长的加减速时间，是预期取舍；不插入逐点等待静止或补发历史命令。
- 松开允许动作键仍走原立即 Stop；未用缓慢减速替代停止。
- 当前插件限制加速度，并未限制 jerk。配置的 max_jerk 字段不代表该插件实际执行了 jerk 约束，不称本次实现 S 曲线。
