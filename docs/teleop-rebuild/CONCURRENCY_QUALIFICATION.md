## 假设与改变

v171 在真实录制时发生约 101 ms 控制回调和候选流超时。单条载荷编码实验不能代表多线程并发，故先用 X5 上同一控制器、ROS 节点和 SDK 解析器作隔离对照。

`scripts/profile_gateway_load.py` 将保留的 1440 字节反馈通过 socketpair 以 125 Hz 输入，控制和操作意图为 20 Hz，可启用两份真实 Audit 写线程。命令接口为即时确认的替身；实际关节固定，不打开 E6、CAN、相机。这只能验证软件争用，不是运动、无线或正式网页资格。

cProfile 发现 362 次 tick 合计约 2.27 s，其中候选 `deepcopy` 约 1.079 s。`MoveItBridge.take()` 现将已接受候选的所有权移交给唯一消费者，并清空 inbox 引用。生产者每次创建新对象，发布后不修改；后续发布及 stop 不改变已接受候选的来源记录。保留原序号、epoch、年龄与期限；不改目标、速度、控制周期或停止规则。

## 真实相机影子剖析

会话 `20261009-033453-f3996f19` 运行正式页面 J6 fine、0.8 倍、每向 0.5 s、六轮连续往返，仅生成候选。使用独立安装的官方 PyPI `py-spy 0.4.1` 对唯一所属网关采样 45 s、100 Hz、nonblocking、threads/subprocesses。工具不加入生产依赖。

采样器报告 1.00–7.32 s 滞后，且采样包含 socket 等待、native 调用和可能复用的线程 ID。文件可定位栈，不能当成准确线程 CPU 比例或实时验收。Audit 的 JSON 编码、IPC 编解码及控制状态计算是后续剖析候选，尚不能单凭样本认定某一项造成全部尖峰。

本次片段保存 2849 周期、17654 原 SDK 帧；原反馈均 Mode5/Enable1/Error0/Collision0、缺号 0。97 个候选的输入身份、epoch、完整来源窗口均无不一致，来源年龄最大 85.839 ms。旧 `audit_moveit_page.py` 的“候选位置减静止实际位置”方向检查在连续反向后失败，原失败输出保留：连续反向中的目标可能仍在实际位置正侧，不能将这个位置差当成速度方向。此次不借此输出宣称完整方向验收通过；后续以独立释放的正负段及原始增量分别核对。

新增独立离线 `analyze_joint_reversals.py`，比较相邻候选的关节增量，仅在前后两个完整来源窗口都为同一方向时检查速度方向；混合窗口保留为过渡，不假称已通过。97 候选含首点 1、同向窗口 48、过渡窗口 48；正负两个方向的 48 项增量均通过，无时间倒退。三项回归覆盖“目标仍为正但速度为负”、真实错误方向及混合窗口，不改生产控制或原方向检查。这补充连续反向解释，不替代来源核查及实机反馈。

录制在约 142 s 触及既有单片段 2 GiB **未压缩原始载荷**预算并中止，原结果保留。它不是磁盘已满或控制器故障。完整封存回传和最终资源状态以本次归档及 STATUS 为准。该问题也说明产品需要提前展示容量与限制；不能简单提高预算后把这次失败改判成功。
