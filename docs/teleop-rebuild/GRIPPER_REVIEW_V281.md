## 初始化与范围

厂家手册 `research/grippers/omnipicker_integration_2026-09-20/official_manual.txt` 的 6.3.1/6.3.2 明确规定 raw 0 全闭、255 全开。当前 15–60% 来源是 `gripper.py` 的软件测试范围，不是厂商额定范围。

现有初始化是发送 35% 目标并核对连续回读，属于实际运动；当前 CAN 协议每收到控制指令才回报状态，文档未提供无动作查询指令。下一版应把连接初始化设为正常会话一次性流程：新鲜设备反馈、静止、模型/相机就绪、操作输入回中后自动开始；同一会话页面刷新、键盘/手柄切换和短暂网页重连不重复执行；已有 fault 不能自动重试或清除。初始化完成不自动 Prepare。

用户要求的全行程应按设备原生 0–100% 表达，不能把旧 15–60% 重标成 0–100%。模型已有 256 开度映射，但名义模型检查不代表当前装配全行程已实测。正常控制仍须保留逐段碰撞检查与未知反馈保护。

优先对当前空载停滞做最小对照：在同一固定机械臂姿态比较连续小目标与单段固定目标、相同速度/力/加减速度，分别检查是否在同一开度停滞。不得改变多个参数后把无法复现当根因解决。该对照尚未执行；本轮未主动运动、清错或重启会话。

## v282：Type-C 对照与研究接口选择（2026-10-17）

用户补充原生 Type-C 手动开合更顺滑，并要求重新评估具身研究应选 CAN 还是原生 USB。此次仅检查历史原始数据、正式源、官方文档及固定固件；没有重新初始化、清错、发送 CAN、切换会话或修改生产参数。

原生 Type-C 实际由同一 USB 复合设备上的 Fibre 控制接口和 CDC 虚拟串口反馈组成，不是用 CDC 发 Modbus 控制。历史 Studio `studio-20260927-032455-60a8bbbb.jsonl`（SHA256 `950a3215ef2cada86a1aa7f1870025dd1c368a19971805d9aef0d3f59201075b`）记录 643 次位置命令及 16,884 条观测，目标覆盖 0–100%，连接时 current_limit=3.0，未记录该会话内调低限幅。Studio 也会连续更新目标，不能把全部 USB 使用概括成单次固定目标；9月27日另一次低速验证才是单目标加6秒观察，且临时 current_limit=1.0。

静态检查固定官方 FW335，SHA256 `0c2ea534143edd90d5351016735cccf523ee4adf72079808324d80b92544df2d`：

- CAN 解码 `0x0801f000` 以 D1/255 为位置，将 D2×1.8/255、D3×3/255、D4×10/255、D5×10/255 写入对象偏移 0x48/0x70/0x4c/0x50，再调用 `0x0801ce94`。
- Fibre schema 构造 `0x08026168` 的偏移与名称关联对应 traj_vel、current_limit、traj_acc、traj_dcc。set_pos 名称在 `0x0802690a` 装配，其函数指针 `0x080269b0` 为 `0x0801ce95`（Thumb），与 CAN 调用同一位置函数。
- 位置函数比较新旧目标，相同目标直接返回；CAN 重复同一目标不等于每次重启一段轨迹。新目标是否造成瞬态须结合运动状态核对。
- 当前停滞阶段速度字节11对应 traj_vel≈0.077647；Force64对应 current_limit≈0.752941；Acc/Dec25对应约0.980392。它们与历史 Studio 默认速度/电流/加减速设置并不等价。这是待对照的重要因素，不能先认定总线造成卡顿或直接恢复全部默认高限幅。
- 这些是哈希固定固件的数据流解释，不是本轮在线USB参数回读，也不是指尖力、负载能力或电流传感器精度标定。停滞的机械/限流根因仍需同姿态、同速度下的最小对照。

离线检查器 `output/inspect_gripper_firmware_282.py` 使用隔离模型工具环境 capstone 5.0.6，只读固件字节。反汇编片段及比较摘要保存在 `evidence/gripper-typec-v282`。本轮只读枚举 PC 与 X5，未见夹爪原生1001:03EF；X5仍为peak_usb CAN适配器。未为探测而打开第二个控制者。

接口建议以当前实现为限：

| 研究需求 | 当前 CAN | 原生 USB Fibre＋CDC |
|---|---|---|
| 开度动作、常规遥操作和VLA抓取 | 已接入正式状态/几何/记录链路 | 原理可行，需实现同等适配与回归 |
| 目标表达 | 8bit、约0.392个百分点 | 浮点归一化；旧Studio界面0.1个百分点，不代表物理精度 |
| 已验证位置反馈 | 8bit、约0.392个百分点 | 当前CDC格式两位小数、1个百分点 |
| 状态与故障 | 公开位置/速度/Force/运动状态/故障同帧 | CDC三列无stalled字段；Fibre可另读故障和配置 |
| 频率 | 历史5/20/50/100Hz请求回包测试通过；当前20Hz | 历史CDC约100Hz；控制事务另计，不能据此声称100Hz闭环 |
| 深层控制实验 | 当前五字段位置协议 | 官方USB接口另有pos/vel/tor/kp/kd；本台运行兼容未验证 |
| 数据同步 | 无设备采样时戳/序号 | CDC也无设备采样时戳/序号；主机100Hz不等于相机同步 |

当前建议保留 CAN 为日常默认，先解决不等价参数及目标策略；USB 是有价值的研发/对照后端，未来涉及阻抗、力矩相关接口时优先评估。选型不是“工业CAN必然更好”，也不是“USB顺滑证明CAN不适用”。无论使用哪种，VLA动作与记录仍经统一夹爪适配，执行端建议集中在X5以共享时钟和控制所有权；同一时刻只允许一个运动命令源。当前USB-CAN路径本来就包含USB，不能称整条路径硬实时。
