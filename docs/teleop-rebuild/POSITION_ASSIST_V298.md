# v298 — Position-priority orientation assistance

Status: candidate B released and low-speed local physical regression passed on 2026-10-18. Full Goal stays paused; autonomous cup grasp remains cancelled. This is not full-workspace, full-speed or physical wireless-receiver qualification.

## Requested behavior

The user selected translation-only input with modest automatic orientation adjustment, using existing keyboard/gamepad hardware. Strict Translation, Rotation and Joint remain available. The new mode is explicit and not the default. It does not add a controller connection or an autonomous task planner.

## Policy

- `Intent.orientation_assist` and `assist_angular_rad_s` are validated independently of ordinary angular input. Assisted input cannot also request angular/joint motion. The backend advertises support only after a versioned binary reports the new protocol.
- The operator's linear vector is preserved. A grasp-TCP Jacobian suggests angular velocity to reduce weighted joint-rate effort; angular motion is penalized and assistance is increased near kinematic/position-limit pressure. The existing MoveIt/KDL path still performs IK, singularity handling, joint limits and acceleration smoothing. The original final swept FCL checks still gate motion.
- Each continuous movement anchors to current actual orientation, with a 15-degree geodesic allowance. Maximum suggested angular speed is 3 degrees/s, further capped by selected speed/fine scaling. Angular suggestions use a two-stage 0.2-second soft start. The final smoothed target is independently checked against angle and angular-step limits.
- Tool-frame input axes are fixed at the movement's initial orientation. Automatic wrist rotation must not turn a straight input into a sideways curve. Release uses the existing Stop path and discards angular momentum; it never requests a return to the old orientation. A new movement starts from new actual feedback.
- The helper is a local velocity policy. It does not prove global reachability, select a distant IK branch, plan around objects or guarantee improvement at every pose. Real collisions, singular stops, stale feedback and execution deadlines remain enforced.
- Audit data records the requested policy separately from generated base-frame twist, anchor, angular allowance, final deviation and rejection reason. The underlying operator angular input remains zero.

## Practical limits

Position assist reduces the need to manually alternate translation and rotation; it cannot guarantee reaching every position. The existing joint, collision and singularity boundaries still apply. Long model-only tests deliberately pushing into collision proximity continue to show rejected frames for both original strict mode and assistance. The isolated 65.6 ms scheduling tail also remains evidence of a possible deadline stop. No full-workspace real-arm test, physical receiver test, cup grasp, depth repair or physical trajectory replay was added in this task.
