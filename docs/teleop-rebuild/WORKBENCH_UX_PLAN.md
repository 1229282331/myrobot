## 调研与复用

核心控制稳定后、正式设计定稿前，完成一轮有边界的公开资料与可运行项目调研。至少覆盖两类学术研究系统和两类工业／工程工具，并核对本项目固定phosphobot版本。候选包括ALOHA、DROID、Open-Teach等示教系统，以及Foxglove、Rerun和机器人厂商操作工具。候选名称仅用于确定调研方向，尚不构成其功能、可复用性或本机效果的结论。

优先官方文档、源码、公开演示及论文配套实现；有条件时实际运行关键工作流。每个候选记录：

- 官方来源、访问日期、固定版本／提交，以及亲测、源码核对或仅文档了解的证据层级。
- 目标用户与主要任务；导航、相机布局、控制反馈、录制管理、时间轴和诊断恢复的设计。
- 值得借鉴的具体行为及其适用场景；不适合当前单臂、无线、研究工位的部分及原因。
- 直接复用、适配组件或仅借鉴交互的选择；依赖、许可证、维护与运行成本。
- 选择后的本地路径、补丁及验证结果，纳入OPEN_SOURCE_REUSE.md。截图模仿不等于代码复用。

形成UX_RESEARCH.md和简明设计决策记录后再实施；不为收集大量项目而无限延长调研。不得把上游宣称或宣传视频当作本机验收。

## 必须做好的工作流

| 工作流 | 最终体验要求 |
|---|---|
| 启动与连接 | 清楚区分模拟、影子、实机；呈现设备状态、控制所有者、输入来源和可执行的下一步。使能、准备与停止语义明确 |
| 连续遥操作 | RGB主视图、模式、坐标系、速度、允许动作状态和停止入口在控制时持续可见；键盘与手柄映射易查；关节、末端及夹爪状态按需展开 |
| 观测与空间理解 | RGB、深度有效性和模型示意各自注明来源与时效；模型／未知开度不得冒充真实状态。布局可合理调整，不让列表或调试信息挤走关键画面 |
| 示教采集 | 任务说明、录制状态、时长／样本、成功／失败／中止和回传进度明确；开始、结束、保存与异常后的恢复不依赖理解内部协议 |
| 研究数据检查 | 浏览真实episode及结果，按样本／时间检查图像、输入、发送动作、确认结果和实际状态；无效关联、缺帧与不确定动作可识别，数据来源和配置可追溯 |
| 诊断与恢复 | 常态界面简洁；异常给出原因、影响范围与可执行恢复步骤，详细日志按需展开。保留一键问题包及本地记录入口 |

任务、物料／场景备注、操作者可选标识、设备与采集配置等元数据应按实际研究需要设计，避免为了表单完整而增加每段录制的操作负担。数据导出只开放已验证的数据类型，现阶段真实动作导出限制仍沿用主规划和实际验收状态。

## 视觉与交互原则

- 使用一致的字体、间距、对齐、色彩、图标及组件状态；中文术语统一、单位明确。复用phosphobot已有设计系统，减少新的依赖与平行样式体系。
- 控制、观测、录制和数据检查有清晰层次；主要工作区服务当前任务，技术诊断和验收脚本收进开发入口。
- 重要状态同时用文字和视觉提示表达，不只依赖颜色；按钮有可访问名称、键盘焦点可见，禁用时说明原因。
- 支持当前PC实际窗口及常见桌面分辨率、缩放；避免遮挡视频、横向溢出或必须滚动才能看到关键控制。无需为手机遥操作扩大本轮范围。
- 文本编辑、下拉框、弹窗、模式切换、页面失焦与手柄断连仍遵守已有输入规则。布局动画和诊断刷新不能拖慢输入或视频。
- 不显示无法验证的精确度、成功状态或实时值；过期、未知、正在回传和已保存状态要容易区分。

## 实施顺序

1. 先完成控制连续性、录制稳定性等当前关键问题；本补充不要求立即切换到视觉开发。
2. 调研并整理主要任务，形成导航与页面草图、组件复用清单，优先拿现有真实片段验证数据检查流程。
3. 在实际上游应用中逐步改版；先用模拟／只读模式验证布局、焦点和状态流转，再接入实机操作验证。
4. 由代理通过正式网页及键盘／手柄映射代输入，完成真实工作流走查，归档最终截图、缺陷处理、使用说明及可回滚版本；用户实体输入体验验收安排在交付后。

## 最终验收

- 调研来源和取舍可查，至少明确一个直接复用点和一个有证据的改进点；不以项目数量代替设计决策。
- 在最终页面完成启动→选择输入→准备→平移／旋转／关节／夹爪→释放→恢复的流程；主要操作无需打开技术诊断或临时脚本。
- 完成录制→标记结果→保存／回传→浏览原图与动作关联的流程；成功、失败、中止均能找到，错误不被隐藏。
- 当前PC实际窗口，以及常见1280×720、1920×1080窗口和125%缩放下检查布局；视频、重要状态和停止入口不因列表、弹窗或长文本丢失。输入和录制有正确的焦点／禁用行为。
- 对空数据、设备未连接、视频过期、未知夹爪、录制失败和回传中的页面作走查，提示提供明确下一步，不把调试堆栈当用户指引。
- 最终界面仍满足主规划中的输入响应、视频及稳定性指标；纯视觉变化只复测受影响项，输入生命周期或控制集成变化补相应功能与实机验证。
- 保存最终页面截图、自动输入工作流检查记录和已知限制至UX_QUALIFICATION.md。上述交付前自动与实机检查通过后可计为前端交付，不等待用户实体输入体验验收；报告如实标明该体验环节在交付后进行。当前文档和临时截图不算通过。
