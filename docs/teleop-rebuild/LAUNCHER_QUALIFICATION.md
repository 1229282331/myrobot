## 实现和依据

`teleop-platform/Start-E6.ps1` 使用固定依赖的独立启动环境。PC 的 MediaMTX 先于相机启动；控制、媒体文件、视频分别通过独立 Paramiko SSH TCP 连接。当前机器已有主机密钥，生产入口拒绝未知或变更密钥；密码只在终端内存使用。

`launcher.py` 检查被复用进程的实际命令与端口归属，验证上游提交和运行制品。每次上传为单独 release，源码逐文件 SHA 保存在 PC／X5；Jazzy 子进程使用同次源码。原网关继续独占设备协议和输入状态，没有新增加控制租约。

`session_runner.py` 监督本次网关与相机，SSH 输入关闭触发正常退出。Linux subreaper 使意外孤儿 ROS 子进程仍归本次 supervisor，可按专属进程组清理；卡住的设备控制者不直接升级强杀。正常退出与崩溃分别报告，保留所有原始结果。

PC 使用上游 uvicorn 生命周期正常退出；实机模式通过上游 `cameras=False` 关闭无关 PC 摄像头枚举。X5 Gemini E 的采集及 WebRTC 路径不变。`/status` 真正可用后才认为本地前端启动完成，X5 另须新反馈、相机和实际 Servo 状态循环就绪。

## 软件回归中的独立问题

首轮完整回归 `145 passed / 1 failed / 4 skipped`，失败是 Windows 的读取句柄短暂阻挡原子替换 `recording.status.json`，原文件明确记录 WinError5 并中止片段，非无线或设备响应超时。原 XML 和失败文件归档于 `evidence/launcher-v40-tests`。

修复仅在 Windows 元数据原子 rename 遇到 WinError5/32 时，针对同一个已写好的临时文件最多等待50ms；不重发录制请求或设备命令。持久权限／磁盘错误照常失败。对应成功替换、旧值保持、永久拒绝及 episode专项30项通过；新完整回归148通过、4项POSIX跳过。Linux设备数据路径没有进入这条 Windows 分支；本轮Linux影子使用的是归档的原函数，按这条明确依赖关系复用，不冒称修改后重做过全部实机测试。4项管道POSIX测试本轮未变，沿用v36的X5实际通过证据。
