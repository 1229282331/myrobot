## 已确认的软件问题

退役 owner `20261019-224907-31ef4663` 完整审计含 5690 条提交和 5690 条确认，7 次 joint_tracking_stopped。原事件、SDK 帧、源码检查及离线复现一致。

1. **5 次 candidate_tracking_error 均为 J5 新目标领先量触及固定 2° 上限。** 候选至实际差为 2.003–2.074°，同帧 QTarget−QActual 仅 0.350–0.470°。停止前 350 ms，J5 仍前进 3.009–3.691°。在这些单调片段中，按历史已发送目标插值得到实际角度对应目标约落后 166–189 ms，控制器目标约落后 134–145 ms；这是片段估算，不是完整闭环时延标定。当前 `JointTrackingGuard.candidate()` 将未执行目标超前距离按同一固定界限硬停，不能区分正常流水线领先与真正跟随失败。旧版本虽然修过持续误差与相邻写入比较，这一处仍未修完整。
2. **2 次 tracking_feedback_stale 是取时顺序竞争。** `Executor.tick()` 在 snapshot 前获取 now，后续使用这个旧 now 调用 observe；反馈线程若在两者之间收到帧，则 now−received_ns 为 −44,083 ns 和 −36,750 ns。当前 guard 将其当作失效反馈并停止。原始事件离线重放均复现；示例改为在 snapshot 之后取时则通过，真正超过 100 ms 的样本仍被拒绝。示例时间用于展示顺序问题，不称原运行曾记录过该修正时间。

此外，部分停止前窗口的指令间隔约 31–89 ms（名义周期 50 ms），控制器目标速度与实际速度都出现波纹，值得继续检查 ServoJ 调度、t=0.1 / aheadtime=50 / gain=500 的组合及目标生成时序。仅凭现有曲线，尚不能把连续运动的全部机械振动归结为某一个参数，或认为上述七次停止解释了所有微抖。
