# v322 网关负载与时序检查（开发中）

2026-10-20。延续用户要求的中高速位移、旋转、联合换向测试；机械臂已重新直连 RDK。到 E6 `192.168.1.4` 的路由为 `eth0 / 192.168.1.14`。本轮已完成下述中速实机回归，无新使能、清错、负载或夹爪位置指令，未 Git 提交。

## 当前结论

v321 在正式网页的中速联合测试中，出现计算已经完成、候选到写口时过期的停止。直连后问题仍出现，不能把原因全归于路由器，也没有校时或机械零位校准的依据。本轮在真实相机和只读平台负载同时运行时，以隔离的官方 SDK 构造器/socketpair/真实 Servo 与 IPC 合成链路复现截止拒绝。

短调用的墙钟耗时明显大于当前线程 CPU 时间，说明有等待/调度开销。现有数据尚不能把它全部归因于 Python GIL、操作系统调度或某一锁。保留全部失败，不称中高速验收通过。

## 测试范围

- 网络和挂载 namespace 内只有 loopback，动作写入口为 socketpair；测试姿态和 150 ms 反馈延迟是合成数据。不是机器人动力学仿真，不是实机运动。
- 33 ms 回包延迟，完整 MoveIt Servo、IPC、最终写口、官方 `Motion`/`RobotControl`、双审计线程和 SDK 反馈解析均参与。
- 外部同时运行实际相机与 `stage=shadow` 网关，增加组合负载；这比正式单网关多一个只读网关，不完全等同生产负载。
- 第一轮使用 cProfile，有测量开销。后续 ABBA 关闭 cProfile，保留超过 2 ms 的方法墙钟/线程 CPU 记录。测试器还多做一次候选 deepcopy，后续 contention 测试移除这一非生产开销，并增加 GC 与锁等待测量。
- 原 37/42/50 ms、100/250 ms、碰撞/跟随/连续性/所有权和停止规则未放宽。模型、TCP、负载和 ACM 未改。
