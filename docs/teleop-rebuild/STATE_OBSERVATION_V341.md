# v341 状态生成与控制锁拆分

2026-10-20 更新：源码与 PC 回归已完成，现已与 v342 合并执行 RDK 相机负载十组测试，5,546 合成发送无控制暂停；Tool 仍有一次退离预算耗尽，整体未通过。未发布到实机控制，不构成实机验收。最终证据见 [INTEGRATED_CHAIN_V343.md](INTEGRATED_CHAIN_V343.md)；下文的“尚未 RDK 验证”等为本候选初始检查点。

v339 故障窗口中，界面状态生成长时间持有输入与 Stop 共用的锁。新 `state_observation.py` 将状态捕获和显示计算分开：只在锁内读取一致的控制、反馈与会话快照，锁外生成夹爪显示几何、TCP 显示变换与静态能力描述。渲染结果只用于观察和审计，不能恢复 Ready、刷新反馈有效期或许可运动。`gateway.py` 的审计与 WebSocket 路径使用该拆分；同步 `state()` API 保留。

正式变更位于 `teleop-platform/src/e6_phosphobot/gateway.py`、`state_observation.py`，专项测试位于 `teleop-platform/tests/test_state_observation.py`。旧源与清单保存在 `output/state-observation-v341/baseline`。

验证结果：

- 完整后端 1192 通过、18 跳过，无失败或错误，原件 `evidence/state-observation-v341/backend.xml`。
- 保存的真实状态在准备/未准备情形下，新旧输出 254 次比较完全一致，原件 `equivalence-wall.json`。
- 专项覆盖显示计算阻塞时 Stop 仍可获得锁、旧快照不能恢复会话、后续 Stop/反馈变化不破坏已捕获快照、显示几何错误局部处理。
- PC 墙钟测量：旧锁内中位 89.3 μs/P95 158.6 μs，新锁内 39.9/P95 46.1 μs；新总耗时 87.4/P95 120.1 μs。不能外推为 RDK 或整机性能。
- 首次 Windows 线程 CPU 时钟粒度不足，保留结果但不作为有效性能证据；WSL 测试因缺少 websockets/fastapi 在收集阶段失败，未计通过。
