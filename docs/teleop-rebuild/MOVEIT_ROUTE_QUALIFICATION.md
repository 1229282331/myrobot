# MoveIt Servo 路线资格检查

2026-10-07。仅记录已完成的实验和仍未解决的问题，不是交付验收报告。

## 为什么进入备选路线

正式网页和独立官方 ServoP 最小实验均复现停止尾部。改变周期、aheadtime、gain 以及 Ruckig 正常释放轨迹未使全部受测动作满足原停止判据。v14 的 1.6 mm 基座 Z 路径在释放后 541.903 ms 才进入原 0.01°／250 ms 稳定窗口，超过 500 ms 最大值；原失败保留。

相同 SDK 和停止方式下，ServoJ 单关节以及控制器 IK 生成的同类笛卡尔路径明显不同：

| 独立诊断 | 实际进入稳定窗口 | Stop 发出 | Stop 回包 | Mode5 且空队列 | 原反馈 |
|---|---:|---:|---:|---:|---:|
| v15 J4 +0.32°，0.32°/s | 164.107 ms | 0.085 ms | 693.741 ms | 655.914 ms | 1182 |
| v16 新控制器 IK 路径，Z +1.6 mm，1.6 mm/s | 183.504 ms | 0.213 ms | 643.627 ms | 649.032 ms | 1246 |

两者均 t=0.05、aheadtime=50、gain=750，无报警，Stop 确认，无自动返回。之前 v15 零关节增量 20 条、834 原包保持正常。它们只说明值得验证 ServoJ 路线，不是正式网页、全部方向、最终速度或统计验收。Stop 回包/模式转换延迟与实际物理稳定时间分开报告。未发 CAN、Enable、清错或持久参数写入。

v14 中最后命令 ID 不变，而控制器目标在 Stop 后仍推进约 250 ms，排除了这段尾部由 PC 继续补发输入造成。分析脚本 `analyze_native_stop.py` 从原始 SDK 字段计算，不使用原探针会不断覆盖的 stationary_ns。该探针字段现已改成首次窗口检测，原实验文件没有重写。

## 固定上游和实际调用

- Dobot ROS2：`0f21e9839888f188ac06b0a9fea622d13a29a74f`。直接检查 `dobot_rviz/urdf/me6_robot.urdf`、原 SRDF、原 STL 和控制器运动学插件源码。
- MoveIt 2 / Servo：2.5.10，`c283a36186a6f7a5985360e6674bf8fd0790e485`。X5 安装官方 ARM64 Debian `2.5.10-1jammy.20260910.035247`，独立运行原 `servo_node_main`，没有启动 Dobot bringup 或第二个 29999 所有者。
- KDL：X5 既有 `liborocos-kdl 1.5.1`、ROS `kdl_parser 2.6.4`。C++探针直接调用 `treeFromFile`、`ChainFkSolverPos_recursive` 和 `ChainJntToJacSolver`，没有另写 FK/IK 求解器。

官方 Dobot 插件的 `getPositionFK` 和 `searchPositionIK` 仍走 KDL；只读源码不能把 README 的“控制器精度”直接当作 MoveIt Servo 实机精度。其示例还使用旋转向量约定，不能不经核对迁移到本项目 RPY 控制器约定。

## 模型核查：未通过

v17 从新实际状态取 49 个附近关节组合，只发送 PositiveKin；v18 查询零关节、各轴 ±45°和 24 个独立广域组合，共 37 个。都是数学查询，没有移动到这些姿态。所有原命令、回包与 KDL 结果保留。

原 URDF 的 base_link→Link6 直接比较：v17 最大 315.376 mm／145.677°；v18 最大 620.299 mm／179.9996°。不能用于真实目标生成。

离散坐标定义假设 `R_controller = Rz(90°) × R_URDF × Rz(180°)` 在两个样本集中的最大绝对姿态差分别约 0.000338°／0.000601°。此前 0.00014°是相对首样本的变化量，不是最大绝对误差。这不是最终坐标标定；模型未修改。

应用该旋转关系后，位置差仍最大约 25.461 mm／21.724 mm。只读零位与单轴 45°的几何恒等式给出以下可辨识总尺寸，**没有用拟合常数补目标**：

| 几何量 | 控制器 FK 推得（mm，近似） | 官方 URDF 对应量（mm） |
|---|---:|---:|
| 底座至 J2 高度 | 165.2 | 166.8 |
| J2–J3 | 189 | 189.06 |
| J3–J4 | 160 | 160 |
| 零位 J4 至腕部竖直距离 | 101 | 101 |
| 腕部至法兰／Link6原点轴向量 | 69.5 | 47 |
| 平行轴合计偏置 | 81.3 | 86 |

外部 FK 只能辨识某些合计量，不能确定它们在多个平行内部坐标系中的分配，也不能证明实体几何、附件或碰撞网格准确。厂家手册 V1.4 第 16 页图 5.1 的 189、160、101 与其中部分一致，但图中 167、65、86 也有差异。下一步应核对模型的物理参考面与本机型号/控制器参数来源，不能把这张表随意拆成关节原点改动并直接运动。

## 软件安装与隔离实验

X5已有 Ubuntu22.04 / ROS2 Humble。安装 MoveIt Servo 前保存 dpkg 清单和 apt 模拟结果；安装只涉及 X5 软件，不改机器人固件/参数。APT 引入 81 个包并升级 7 个系统依赖，安装时 D-Bus 重载导致等待连接重置；随后通过 systemd 状态和 dpkg 回读确认安装完成，非机器人控制中断。详细清单和日志存 `/root/e6-teleop-rebuild/ros-setup-v17`，需随发布保存固定包版本。

隔离节点限定 localhost、ROS_DOMAIN_ID=87，虚拟 JointState，输出只写 candidate 文件；无 Dobot/CAN 导入和实机发送路径。原 SRDF 与碰撞检查保留，视觉 STL 不改。

- 首次在安装尚未结束时导入失败（control_msgs缺失），保留启动失败。
- 原高精度 STL 导致初始化超过测试的 5 秒／30 秒等待；中断初始化产生上游退出异常。v17、v18失败日志保留，不把延长启动等待当实时控制优化。
- 后续采用 Trimesh4.8.3 / SciPy1.15.3 QHull 生成保守碰撞凸包。原始两个凸包不闭合被拒绝；10 μm坐标网格、最小100 μm外扩后，重新检查所有未量化原顶点包含关系和闭合性。仅是理论CAD包络，不代表模型或附件几何已验收。

当前生产仍为既有 ServoP/gain500、2 mm/s、1°/s。MoveIt 实机控制未开放，原始反馈、相机、停止、记录功能不依赖这份未对齐模型。

### v19／v20实际软件结果

保守凸包覆盖检查通过，原368132三角面降到17060面。v19官方节点正常运行，600候选、暂停/恢复/退出成功；原SRDF home姿态的6个笛卡尔方向触发上游奇异状态2，因此不能称方向矩阵通过。v18初始化SIGINT后的原退出失败保留。

v20只替换**虚拟**起点为v18保存的实际关节值，保持相同奇异阈值、碰撞检查和限速，没有连接真实设备。24方向（6关节正负＋6末端轴正负）均输出非零候选，共601条；另由KDL读回各组端点，24组方向符号/方向余弦检查全部通过。运动期间保留状态1/6（接近/离开奇异时减速），不拿释放后的状态0覆盖它们。暂停、恢复、停止服务和进程退出代码0。尚未测定正式网页输入、持续速度、传输时延或物理停止。

结束后5秒610新被动反馈：Mode5/使能/无报警/空队列，最大关节峰峰0.006867°，无订阅丢包；E6连接、ROS资格进程和视频占用均释放，CAN DOWN、RX/TX仍10959。PC原工作台和MediaMTX保持运行，网关未连接。
