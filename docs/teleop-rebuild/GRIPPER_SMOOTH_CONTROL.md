# 夹爪连续开合 v272

本次只处理用户反馈的开合顿挫，完整 Goal 保持暂停。机械臂不主动运动；真实测试从新反馈开始，通过正式键盘／合成手柄链路，在既有空载 15–60% 开度内进行。

## 发现与方案

v271 用户会话原始回读显示：0.8x 输入期间，新目标通常每约 200 ms 增减 4 个 CAN 计数，实际速度反复升降至接近零。四计数合并原为 v72 小步命令未到位的补救，不是连续随动方案。不能直接删掉历史失败证据、提高夹持力或把显示插值当作实物流畅。

最终实现使用厂家 CAN 位置、速度及原加减速字段：输入速度积分为参考位置，并生成 4 计数前置目标；目标距实际反馈最多 8 计数，等待几何许可时保留同一待检目标，避免许可追不上目标更新。反向从新实际反馈开始，松开选择一次近反馈保持目标；CAN 自身额外监控 250 ms 输入更新超时。力64、加减速25保持。所有新位置仍经过现有 FCL 全段检查。

厂家速度字节没有公开绝对单位。旧用户开合两段实际位置增量／反馈速度积分分别约 1.948、1.900 counts/s per velocity byte，候选采用 1.92 估算并以实机测试核对。不是厂家标定值，不用于夹持力或毫米速度承诺。

协议位置仍为 8 bit；连续操作指不再刻意攒四计数再走一步，不宣称无限位置分辨率。最低速度字节和低倍率下的实际效果也必须单独检查。

## 验证状态

首轮160项、第二轮161项相关后端及30项数据关联检查通过。首次8个失败来自旧CAN替身不接受新增速度参数，已更新替身；保护条件没有修改。

第一候选正式键盘9段开合均无设备报警，58,775原SDK反馈无缺号，机械臂命令编号全为1572，没有主动机械臂命令。0.8x稳态速度字节9–12，精细25%为1–3；两者输入内段没有回到速度零。覆盖上下端点，原始全段数据保留。最低0.1x暴露松开后仍完成前置目标、收尾超过2秒的问题，第一候选不作为最终交付。

第二候选对同一位置发送厂家范围内的零速度，实机仍继续以原速度运行约0.5秒至目标；不能把此方法当停止。保留原CAN字节与反馈，撤销此候选，不扩展零速度到生产协议校验。

第三候选松开时只选择一次近实际反馈的保持目标，沿已提交目标方向留约150 ms行程且至少1个编码计数，不越过已提交目标。该新目标仍走原FCL许可；反复中立输入不会追着反馈改目标。新输入从新实际反馈重新开始。此项改变只缩短已提交行程的收尾，不增加夹持力、不提高运动速度。192项相关检查通过。正式低倍率键盘正反和50%扳机正反四段通过；低倍率从网关收到释放至首次到位约117–163 ms，半扳机约290–352 ms。34,854原SDK帧无缺号报警，命令ID1572不变。

最后用独立执行器替身复现了另一种情况：FCL许可延迟后，夹爪可能已越过原先选择的保持点；迟到目标会造成反向。最终D版丢弃这种过时保持点，只完成原先已经提交的行程，不补发反向、不追随反馈重选停止点。正反两例由失败变通过。194项相关后端检查及另外2项极低速度有界位移检查通过；测试替身覆盖的是软件语义，不代替下面的实机结果。首次命令中测试文件通配符未被PowerShell展开的“no tests ran”也保留，不能计入通过数。

测量方法：输入开始后300 ms至释放前100 ms作为固定内段；斜率用原始CAN位置首尾差计算。释放计时起点是X5网关收到中立输入，不是浏览器按键时间；CAN反馈与输入使用同一单调时钟，反馈约50 ms一次，位置量化1/255。首次到位要求原始state=0、velocity=0、位置误差≤1计数；稳定确认要求这些条件持续至少200 ms，表中为确认完成时间。全段（含起停、低速、端点和失败候选）保留，未把低速段删掉后宣称整体达标。

普通段原始速度字节9–13，精细段1–3，固定内段均无速度零回读；旧用户0.8x片段可见0–19/24及四计数阶跃。两次姿态、长度和端点条件不同，此处仅作为现象对照，不宣称严格同轨迹A/B统计。D版41,585原SDK帧连续、全部Mode5/Enable1/Error0/Collision0，命令编号全为1572，无主动ServoJ。关节峰峰最大0.022660°，不宣称物理完全零位移。6,275份唯一FCL结果无几何拒绝/预算耗尽，显示与实际开度对应的8关节映射无错配。等待新目标许可的60次短暂`gripper_collision_blocked/resumed`事件仍保留；它们是现有布尔接口中的等待状态，不是新增设备碰撞。

极低速限制明确保留：0.1x再叠加25%仅请求0.25百分点/秒，已低于速度字节1的实际能力。此时短段实测约0.62–0.77百分点/秒，原始速度0/1量化明显；不能称精确按比例或完全匀速。长期位置前置仍有上界，松开不保留积分积压。硬件位置为8 bit（约0.392百分点/计数），这次是连续操作改进，不是无限分辨率或任意低速能力升级。空载验证不代替接触物体后的力控/形变标定。

## 发布与回滚

前端、CAN编码器、机械臂求解器和所有力/加减速上限未改。正式修改是`src/e6_phosphobot/gripper.py`的连续率控制与`gateway.py`的调用；精确位置API保留原批量规则。快照分别给出位置API四计数阈值、连续API一计数更新能力及速度下限估计，结构化审计照常保留原始CAN。

D测试会话正常clean退出，恢复schedutil。日常operator使用相同源码、关闭合成输入，经正式初始化后保持未准备供用户体验；最终会话状态见STATUS与`operator-final.json`。完整Goal仍暂停，本次不声称完成全平台验收。

回滚包`output/gripper-smooth-v272/baseline`及正式包`release`都有SHA清单。先在页面Stop、确认静止且录制idle，通过对应stopfile正常退出自有会话。运行：

```powershell

teleop-platform/.venv-launcher/Scripts/python.exe teleop-platform/scripts/switch_gripper_rate_v272.py --rollback
```

再用日常启动器启动，由原部署路径核对并上传源文件。脚本只恢复本次两个源码文件，拒绝覆盖后续未知修改，拒绝在本地服务仍监听或最近会话未clean退出时切换；不执行设备命令、不改配置、模型或数据。去掉`--rollback`可重新选择本版。

当前源文件、旧源文件及本次证据分别保存在正式 src、output/gripper-smooth-v272/baseline、evidence/gripper-smooth-v272。机械臂模型、二进制、工作空间、TCP、负载、速度及柔和起步不变。
