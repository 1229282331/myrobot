# V354 候选传递与指令流期限联合调整

用户允许根据操控体验合理放宽人为限额。本次针对 V353 两次非计算超时中断，原生计算仍使用正式候选 d5551ee2 的 55/70 ms 回调/请求、50/48 ms 退离/几何预算，积分和最短发送周期仍为 50 ms。

## 当前实现

增加显式、版本化 `delivery_timing` 清单，只有固定求解器和单写口回执节拍路径允许启用：

| 项目 | 原路径 | 新候选 |
| --- | ---: | ---: |
| 原始求解反馈到最终写口的有效期 | 100 ms | 150 ms |
| 候选流断档等待 | 150 ms | 200 ms |
| 当前设备反馈新鲜度 | 100 ms | 100 ms |
| 当前输入有效期 | 250 ms | 250 ms |
| 最短相邻写入间隔 / 积分步 | 50 ms | 50 ms |

有效期绑定原始反馈和原始输入时间戳，发布、获取新反馈、等待写入时均不续期。求解器仍只允许一个未提交端点；没有实际发送回执就不能生成下一步，不积压后补、不重置跟踪目标来掩盖未执行点。最终写口仍检查最新设备反馈、跟随和关节连续性，以及当前夹爪是否在该段已检查的开度范围内。夹爪自身新运动的几何许可期限没有修改。

同时修正过期端点的可见性：采用单写口回执节拍时，worker 不再悄悄把未提交的过期点变成 candidate=null。它保留原始截止并通知消费者拒绝、取消本轮输入，以免生产端永远等不到回执。未采用此节拍的旧路径保持原唤醒行为。

正式来源：`delivery_timing.py`、`cpp_cycle.py`、`jazzy_cpp_worker.py`、`jazzy_host.py`、`moveit_bridge.py`、`gateway.py`。原件、当前源码、可复现补丁在 `output/delivery-timing-v354`；补丁已逐字节重放。
