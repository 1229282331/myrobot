## 假设与改变

v182第三组释放序号2697已在X5收到，执行线程仍持控制锁。5.592 ms后旧候选触边，随后Stop，最后才处理释放。v170也记录过释放等待控制锁期间提交旧目标。收包线程等待长计算锁是可复现的软件竞态，与控制器微小收尾不同。

拥有者socket在等待控制锁前校验消息，合法递增的显式stop或deadman=False释放只登记取消标记。执行线程在候选计算、工作区评估及提交目标前检查标记，经原Stop路径停止；夹爪保持原最后目标。已发送但未确认的命令仍保留并处理原回执，不盲目重发。

最初未部署草稿将deadman=True的零轴和record_finish也提前取消。离线评审发现它们可能因旧echo或无录制配置被原协议拒绝，造成先停再续旧输入；最终实现只对原协议本来就优先撤销动作的stop/deadman=False生效。实验ruckig释放语义保留。检查点与实际入队之间仍有普通调度窗口；本修复不是硬实时原子制动承诺，已提交命令由Stop及原回执处理。
