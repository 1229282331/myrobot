## 问题与修改

旧关联先找动作前最近的20Hz图像采样，再取该采样中的图。部分原图已经在动作前到达SDK，但在下一次20Hz采样才被记录；旧算法会漏选它们。

新片段元数据声明 `action_association_policy=sdk_available_v2`。从已校验原图清单选取动作发送前已从SDK取得的最新帧，要求原始 `host_perf_counter_ns <= action_sent_ns`，并继续以源接收时间计算100ms有效期。内核已收到但SDK在动作后才取出的积压图不能被选中。SDK/源时间、capture_epoch、帧编号分别保存，写盘时间不冒充采集时间，不宣称曝光同步。

没有新规则标记的历史片段仍用 `sample_before_action_v1`。重复校验时已有动作关联必须与重新生成结果一致，不能静默覆盖历史分析。真实动作仍来自原始发送事件及确认，未从下一帧状态补动作。
