# DaBai DCW：E6 腕部相机任务适配与接入评估

日期：2026-09-24。用户明确回到DCW作为当前选型方向。尚未确认采购、到货或实机验证；本轮没有安装驱动、运行相机/机器人或联系卖家。

## 结论

对室内桌面小物体抓放、分类、轨迹示教数据采集，以及基于RGB的ACT、Diffusion Policy、π0.5适配，DCW的规格足以作为第一台腕部相机。工程前提是实物RGB在实际工作距离清晰，驱动和采集稳定、时间戳可用、安装遮挡可接受。

主要优点是低成本、完整RGB-D、宽RGB视场、单USB线供电通信、成熟厂商旧版SDK和Python/ROS2资源。主要限制是20cm深度近端、旧SDK生态、USB2输出模式约束、无实机帧时序/延迟验证，以及E6剩余负载紧张。

## 硬件核查

本轮重新逐页查看官方《对外版DaBai DCW-DW Datasheet V2.5》PDF第5–7页。

| 项目 | DCW规格与含义 |
|---|---|
| 原理 | 双目结构光，提供RGB、深度、IR；DW不带RGB，不能混买 |
| 重量/尺寸 | 88.3±3g；89.82×25.10×25.10mm；未实称二手机 |
| 深度距离 | 0.2–2.5m；不足20cm不能作为有保证的有效深度范围。彩色最近清晰距离需另测 |
| 未D2C深度 | 640×480、512×384等最高30fps；1024×768仅5/10fps；深度单位可为0.1mm或1mm，读取实际单位，不等于精度 |
| D2C | 相机D2C支持640×360/320×180最高30fps；软件D2C的1920×1080/1280×720仅5/10fps。像素对齐不会凭空增加真实深度细节，也不等于与机器人状态的时间同步 |
| RGB | 1920×1080和1280×720的MJPEG模式支持30fps；YUY2的1080p仅5fps，720p仅5/10fps。640×360的MJPEG/YUY2可30fps |
| RGB视场 | V2.5：16:9 H84.3°/V53.6°，4:3 H67.8°/V53.6°，标注±3°；网页分别写H86°/H64°、V55°。工程上约84–86°宽画面，不能把16:9宽视场套到4:3模式 |
| 深度视场 | V2.5未D2C为H79°/V62°；相机D2C约H79°/V53.6° |
| 供电/数据 | USB2.0 Type-C一根线；平均<2.3W、峰值<5W。网页介绍段<1.2W与参数表不一致，PDF表区分DCW<2.3W、DW<1.2W，不采用混合宣传数值 |
| 安装 | 后续安装章节复核纠正：V2.5 §3.4.1（PDF第19页）明确支架用2颗M3，有效牙长4.5mm、建议支架厚2mm、螺钉长6–6.5mm。参数表2×M2与此冲突；§5.1结构图将USB处2×M2标为数据线锁固孔，另有M3标注（该图标有效牙深5.5mm，与正文也有差异）。设计先用正文较保守的4.5mm边界、2mm支架配M3×6候选，实物确认孔径、孔距及深度后定稿，不默认1/4摄影螺孔。详见安装方案文档 |
| 环境 | 室内、10–40℃，基础防尘；不当作户外强光或防水工业测量相机 |
| 精度 | 厂商表：中心81%区域，1m处相对精度1%，2m处1.1%。不能外推为20cm处必然2mm，也不能由0.1mm深度单位推出0.1mm精度 |

透明、镜面、低红外反射物和强光属于该类光学深度的常见困难；具体DCW样机效果待测。RGB快门类型本轮未找到可靠规格，不能称其为已验证全局快门。图像模糊还取决于照明、曝光与运动速度。

负载算术：夹爪暂按430g＋R2铝盘理论54.36g＋DCW标称88.3g＝572.66g；E6标称750g减后剩177.34g，需共同容纳相机支架、紧固件、随动线缆和被抓物，还受重心/动态力矩约束。不能宣传为可抓177g。工程上先做几十克物品、再实称整套末端。

| 开发板 | SDK v1列Linux ARM64 Ubuntu18.04/20.04/22.04，列出RK3399/树莓派等平台，未直接列RDK X5、RK3588。两块板有可实施路径，但非已验证即插即用；底层预编译库、Python ABI/系统版本须匹配，无需NVIDIA GPU来计算DCW深度 |
| LeRobot/openpi | 当前LeRobot内置列表没有DCW专用Camera类。若RGB能通过系统视频节点可靠读取，可走OpenCVCamera；否则用对应Python SDK封装Camera适配器。RGB-D策略需追加深度、单位、内参和对齐处理，不把RGB接入当成已完成点云适配。openpi主要需要对应图像/机器人状态/动作格式，不限定必须RealSense |

生态判断：厂商基础驱动和ROS集成有明确资源，具身工具中开箱即用程度弱于RealSense；DCW属于维护旧设备的路线，最新开源v2的全部特性不能套用。对一套低成本研究原型可接受，对批量长期复制需固定软件/固件并保存安装包。

## 对任务的边界

- 适合起步：小方块/纸盒/日用品抓放、分类、摆放，RGB示教和ACT/DP/π0.5数据适配。算法成功率不是相机规格保证。
- 深度辅助定位、桌面平面和粗点云可尝试：在有效量程内，读取正确内外参、单位并完成相机到机械臂坐标的标定。
- 不保证：镜头前10–15cm仍有完整深度、透明玻璃/镜面金属的精确重建、亚毫米插装、高速视觉闭环。视觉30fps不意味着机械臂只能或应该30Hz控制。
- 仅一台腕部视角可完成简单起步任务；长时任务、多个目标搜索及夹指遮挡明显时，后续固定全局RGB视角可能比提高腕部相机规格更有帮助。

## 建议接入和验收

接线：DCW → USB → 底座旁RDK X5或Orange Pi5 Pro → 局域网 → PC。开发板不放腕部，相机不接E6的PNP接口；USB线仍沿机械臂布置和做应力释放。

先在Windows匹配v1 Viewer验收，再迁移开发板。建议初始目标为RGB 1280×720@30 MJPEG，深度640×480@30；两路分别验证后再测试双流。若用相机D2C再按其640×360模式配置，不假定任意RGB/深度模式都可同开满帧。

验收项目：确认实物DCW型号/固件；镜头前15/20/25/30cm分别检查RGB清晰度和深度有效区域（15cm不是必须深度合格）；连续录制30分钟观察实际帧率、掉帧、USB重连、曝光、温升及时间戳；安装后检查是否同时看见两指接触区、夹持物和周边桌面。若接触阶段镜头距离不足20cm，应明确此阶段主要使用RGB，不能靠插值补出真实深度。

建议在开发板记录相机时间戳、主机单调时间及帧号，与E6实际反馈/夹爪反馈对齐；Wi-Fi接收时刻不能直接当曝光时刻。训练与部署使用一致的焦距、安装、裁剪/缩放流程；16:9图像转方形模型输入时避免裁掉夹爪两侧，并相应更新几何内参。
