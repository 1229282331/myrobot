# RDK X5 上电无灯排查（尚未定位）

日期：2026-09-29。仅用户现场反馈与公开资料核查，未连接开发板或读取 TF 卡。

## 用户已确认

- RDK X5 上电后无反应，散热风扇转，板上指示灯不亮。
- 使用 5V/5A 电源，接 PWR Type-C 口；绿色灯从上电开始也完全不亮。
- 插有 TF 卡，但不记得是否烧录过系统，也不确定这块板以前是否成功启动。
- 电源额定规格和接入端口来自用户确认；没有实测板端带载电压、板内电源轨或启动日志。尚无短路、异常发热、引导升级等历史的确认。

## 资料核查与判断边界

1. 官方 X5 硬件介绍要求 5V/5A，称绿色电源指示灯亮表示供电正常，3.1.0 版本后橙色状态灯闪烁表示系统运行正常。
2. 官方 X5 启动系统页又写“绿灯点亮代表系统启动中，熄灭或闪烁代表系统启动完成”。两页对灯的描述存在差异，不能据此断言某盏灯在所有软件版本、所有启动阶段必然常亮。
3. 已提取并视觉复核官方 `RDK_X5_IO_CONN_PUBLIC_V1.1.pdf` 完整单页。该页为接口原理图，包含 PWR 输入、40Pin、TF 和调试串口等；未给出板上 PWR/状态灯驱动电路及完整电源管理电路，不能用它证明空卡时电源灯的必然状态。图中 RJ45 的绿/黄灯属于网口，不能当作板上电源灯。
4. 官方 X5 FAQ 将电源和启动介质是否烧录系统列为不开机的基本检查。空卡或仅复制镜像文件无法替代系统镜像烧录；但还没有检查用户卡的实际内容。
5. 官方论坛有指示灯全灭、串口无打印、更换/重刷卡无效且疑似引脚短路的维修案例。用户当前没有这些完整证据，不能直接套用坏板结论。论坛机器人自动回复未作为定论依据。

当前结论：尚不能认定主板损坏，也不能将无灯全部归因于 TF 卡。风扇转只证明其供电路径有电，不证明主芯片已启动或全部电源轨正常。

## 待执行步骤

1. 开发板断电后取出 TF 卡，用读卡器连接电脑；Windows 若提示格式化，应取消。
2. 先只读检查分区和启动文件，确认是否存在 X5 系统。单凭 Windows 不识别 Linux 分区，不能认定卡空白或损坏；存在启动文件也不等于系统完整可启动。
3. 若需重烧，先核实卡内数据和目标磁盘，使用官方 X5 镜像写入并校验。当前未授权覆盖任何具体磁盘，未下载/烧录镜像。
4. 若镜像与卡均确认正常而仍无法启动，使用普通 X5 的 Micro-USB DEBUG 接口读取启动日志，官方参数为 115200、8N1、无流控。调试口连接电脑不替代 PWR 供电；只收日志，不发送刷写或启动控制命令。出现串口设备本身也不等于 SoC 已启动。
5. 在确认串口线、端口和接收设置正确之后，再结合日志或无输出、板端电压等证据决定是否送检。
