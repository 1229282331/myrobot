## 已交付和范围

| 入口 | 用途 |
|---|---|
| `tools/grasp_task.py` | 默认离线验证；显式模拟或实机执行 1–5 轮，默认 3 轮 |
| `tools/grasp_task_plan.py` | 生成离线示例，或显式读取控制器 IK/FK 准备新预览；不使能或运动 |
| `tools/grasp_task_scene.py` | 默认离线说明；显式采集已使能、已到固定悬停点的新场景；不打开 CAN、不使能或运动，异常可以 Stop |
| `tools/grasp_task_vision.py` | 固定瓶体位置、接触图、10 mm 试抬和原位释放的图像检查 |
| `tools/grasp_task_hardware.py` | X5 后端：一个 Dashboard、一个 CAN 所有者、相机子进程和资源清理 |
| `tools/verify_grasp_task_offline.py` | 封锁 socket 和硬件子进程入口，运行测试、默认 CLI、3/5 轮模拟与真实历史图像回归 |
| `config/e6_fixed_grasp_profile.json` | 固定物料、历史局部几何、夹爪限幅和已知相机运行环境 |

当前仅支持原来这只蓝盖透明小瓶、原来工位和原位放回。物料坐标与相机到法兰变换固定；图像检查用于拒绝位置变化，**不会从一张新图自动生成新的三维抓取目标**。新物料、新位置、横向搬运和自由空间避障都不包含在这一版。

手眼数据仍保留 `validated_for_motion=false`，夹指 TCP 仍未实测。URDF 关节原点与控制器坐标有差异，170 mm 工具球和桌面 Z=-22 mm 是局部名义估算。这些限制不能通过软件测试消除。每次上机仍需新状态、新画面和当前路径净空核对。

## 流程与停止规则

当前程序每轮执行：预检 → 张开 60% → Z280→300 mm 观察上移 → 新图确认固定瓶体 → Z300→280 mm 返回 → 法兰 Z=280→240→210→190 mm → 10% 目标夹持 → 接触图检查 → 试抬 10 mm → 图像验证 → 再抬 20 mm → 记录最高点图 → 原位返回 Z=190 mm → 张开释放 → Z=235→280 mm 撤高 → 再到 Z300 mm 取得同高度新图 → 图像和开启反馈确认释放 → 回到 Z280 mm。每轮通过后才进入下一轮，所有轮次通过后恢复默认完整末端收臂姿态。初始观察上移/返回已在单轮演示中实机通过；该演示未到高位释放检查，释放后的观察往返仍未完整验收。

夹爪沿用历史通过的 Vel=10、Force=64、Acc/Dec=25 原始限幅。接触判定要求真实闭合进展、非零位置、20 帧稳定 state2；抬升期间持续检查夹持。state2 只是闭合阻力证据，必须再通过试抬图像检查。近桌面 LDP 保护可能让深度全零，本流程不补洞，也不关闭保护来构造距离。

运动沿用每段 ≤3°、9 个 FK 采样、1% 速度/加速度、cp=0、关节包络 ±0.15°、XYZ 包络 ±1.5 mm、完整查询 ≤1 s、30 s 到位超时和 5 次稳定到位。夹爪守护为 20 Hz，反馈过期门槛 0.3 s。每轮预算 600 s，最终收臂预算 300 s。

抓空、失联、滑落/夹持变化、运动越界、图像不通过、取消或日志 I/O 故障都会中止，Stop 最多发送一次。Stop 不依赖日志写入；回复超时不会被改写成成功或自动重试。失败后不继续后续阶段，不自动释放物料、回位、清错、重使能、下使能或关机。清理仍逐项尝试相机、守护线程、CAN、连接和文件锁；无法确认清理时不报告成功。

成功后保持使能待机。每次用户要求下机，仍按 AGENTS.md 的约定另行检查、下使能和关闭 X5。默认目标是 `[-66.5019,-60,105,-90,90,9.1974]°`；历史下使能回落没有修复。本程序结束并将 CAN DOWN，不证明 E6 末端夹爪 24V 已断。

## 软件验证与本次实机

最新 82 项离线检查位于 `docs/evidence/grasp_task_live_20261004/verification_elevated_view_final/`。高位定位失败禁止返回及下降，释放失败禁止返回或收臂；观察高度和路线连接固定。旧竖直脚本默认 Z 上限仍为 285.01 mm，只有任务中的独立观察腿允许到 300 mm，抓取路径、力度、图像门槛和运动／通信保护不变。初版 78 项检查是下方历史软件证据；新的实机结果单独保存在 `docs/evidence/grasp_task_live_20261004/`，不能把模拟成功或离线重算改写成实机成功。

最终证据位于 [verification_final](evidence/grasp_task_software_20261004/verification_final/)：78 项相关离线测试通过，其中 49 项是本轮新增测试；3 轮、5 轮模拟均完成循环与收臂，`physical_success_claim=false`、硬件连接数为 0。默认 CLI 不连接设备，历史 `offline_example` 即使加 `--execute` 也在连接前拒绝。固定 SHA、过期预览、源码变化、计划断开、改高度/力度、抓空、夹持变化、反馈超时、运动失败、取消、日志失败及部分初始化清理均有拒绝/停止测试。

历史图像回归覆盖悬停、接触、10 mm 试抬和放回。试抬回归瓶体质心位移 0.385 px、桌面预测位移约 10.48 px、211 个桌面内点，轮廓 Dice=0.993。无真实图像运动、纹理不足、缺目标、多候选、错误内参、镜像、30 mm 冒充试抬和物料位移会被拒绝。它们是历史图片回归，不是新的实机抓放结果，也没有直接测量瓶底净空。

悬停定位改用完整蓝色轮廓，避免小 ROI 截断造成位移漏检。历史悬停轮廓质心相对瓶盖投影的残差约 5.9 px，放回前后完整轮廓差约 5.85 px、Dice=0.923；它们包含瓶体形状和视角差异，不是绝对抓取精度。图像门槛为投影残差 ≤8 px、放回质心差 ≤8 px、Dice ≥0.85，且完整轮廓不得触及搜索边界。

模拟竖直 FK 采用明确标记的插值数据，收臂部分包含历史计划，整个 bundle 都是 `offline_example`。没有把历史 285 mm 起点的第一段拼成 280 mm 闭合实机路径。实机预览会从本次实际悬停关节重新查询 IK/FK，并重新采样收臂路径；不重放历史 21 段。

## 本机复现：无需开机

在仓库根目录 PowerShell 中运行，所有输出目录都必须是新目录：

```powershell
.\dcw\.runtime\python.exe -m tools.verify_grasp_task_offline --output docs/evidence/my_offline_check
```

也可分开运行：

```powershell
.\dcw\.runtime\python.exe -m tools.grasp_task_plan --example --output tmp/grasp_example
$graspBundleSha = (Get-FileHash tmp/grasp_example/bundle.json -Algorithm SHA256).Hash.ToLower()
.\dcw\.runtime\python.exe -m tools.grasp_task --bundle tmp/grasp_example/bundle.json --sha256 $graspBundleSha
.\dcw\.runtime\python.exe -m tools.grasp_task --bundle tmp/grasp_example/bundle.json --sha256 $graspBundleSha --simulate --cycles 3 --output tmp/grasp_sim3
```

## 下次实机准备与执行

以下是以后上机和接续的准备步骤；本次实测和当前保持状态见实机报告。先完成开机后的只读设备核查、负载/TCP/末端安装核对、新画面检查，按新起点规划使能和到达固定悬停点；这些动作不由循环程序自动完成。关机后实际腕姿态与关机前目标可能不同，不能直接使用旧起点。夹爪应为空，瓶子在桌面原位置，肩肘、腕部附件、竖直路径、高位观察往返和收臂走廊及线缆都需核对，人员离开并可现场急停。

将项目源码和固定模型完整复制到 X5 项目目录，保留相对目录与原始文件字节。相机仍使用 profile 中已有部署路径，脚本和 XML 的 SHA 必须一致；不得为了让执行通过而改预览哈希或绕过起点检查。

在 X5 仓库根目录，已使能且到位后：

```bash
python3 -m tools.grasp_task_scene --capture --output /root/grasp_scene_NEW
python3 -m tools.grasp_task_plan --live-preview \
  --scene-observation /root/grasp_scene_NEW/scene_observation.json \
  --output /root/grasp_preview_NEW
```

先检查新预览的完整竖直路线与收臂扫掠，并核对现场净空。无 `--clearance-review` 的预览可以审阅和模拟，不能实机执行。准备当前现场核查记录，例如：

```json
{
  "checked": true,
  "checked_utc": "实际核查时刻的带时区 ISO 8601 时间",
  "note": "写明本次瓶子/空夹爪、竖直与收臂走廊、肩肘腕附件和线缆、人员与急停核查结果"
}
```

这份记录只能根据当前事实填写，不能复制示例当作已核查。新采图后重新运行 `--live-preview` 并增加 `--clearance-review /root/current_clearance.json`；采图进入准备时须 ≤180 s，预览与现场核查进入执行时都须 ≤30 min。准备工具只读，不会帮机械臂到悬停点，也不会补使能。程序只支持历史悬停关节附近 ±0.03° 的局部工位；拒绝起点时重新核查和定位，不放宽保护。

审核通过后，读取 `preview.json` 中 `bundle_sha256`，在同一部署目录显式执行：

```bash
python3 -m tools.grasp_task --bundle /root/grasp_preview_REVIEWED/bundle.json \
  --sha256 ACTUAL_BUNDLE_SHA --execute --cycles 3 --output /root/grasp_run_NEW
```

执行前会重新验证 bundle、源码、相机配置和新起点，第一轮还会取得新的悬停图。`SIGINT`/`SIGTERM`/`SIGHUP` 或 `/root/omnipicker-can/STOP` 会取消任务；失败后先核查现场、实际保持状态和停止证据，不自动重跑。

输出包括 `events.jsonl`、`bundle.json`、`summary.json`、各运动/夹爪阶段报告、相机 RGB/深度/原始时间戳记录、新图与 CAN 传输记录。JSONL 含阶段、轮次、主机 UTC/单调时钟、关节/法兰、命令和真实夹爪反馈；机器人模式使用 `robot_mode`，与运行模式分开。各阶段落盘并 fsync。主机接收时间和正确 RGB PTS 不等于曝光同步，当前输出也不是已完成的 LeRobot 训练数据集。

若准备图明确因下沿截断拒绝，可在只读 `--live-preview` 增加 `--plan-elevated-view-from-clipped-scene`；仅为新采样观察路线作准备，目标状态记为 `deferred`，不是定位通过。其他目标错误仍拒绝；真实执行必须先上到 Z300 mm 取得完整新图并通过定位，才会下降。现场核查记录仍需当前事实和实际时间。

接续实机先完成高位观察和 3 轮连续验收，分别记录接触、试抬、放回和停止情况；通过后再验证 5 轮。重复成功率和横向 A→B 搬运仍待实测。
