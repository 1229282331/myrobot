# Magician E6 资料与软件生态

核查日期：2026-09-16。下文区分已确认的官方支持、可用于集成的通用工具，以及仍需核实的适配。

## 1. 先确认型号与硬件边界

来源：[E6 官方产品及参数页](https://www.dobot-robots.com/products/education/magician-e6.html)。页面 Specs 显示：

| 项目 | 官方参数 | 对当前项目的意义 |
|---|---|---|
| 自由度 | 6 轴 | 可以控制末端三维位置和姿态；实际可达范围仍受关节约束与奇异位形影响 |
| 额定负载 | 750 g | 将来安装夹爪、相机和支架时，要把附件和物体共同计入负载并核对重心约束 |
| 工作半径 | 450 mm | 适合桌面实验；不是以底座为中心任意方向都可达的完整球体 |
| 重复定位精度 | ±0.1 mm | 不是绝对定位精度，也不是视觉抓取精度 |
| 本体重量 | ≤7.2 kg | 需要按手册固定底座 |
| TCP 最高速度 | 0.5 m/s | 产品上限，不作为初次实验速度 |
| 最大关节速度 | 120°/s | 同上 |
| 通信 | 2 个 Ethernet，TCP/IP、Modbus TCP | Python 控制及外设通信入口 |
| 末端 I/O | DI×2、DO×2、24V×1、GND×1 | 可用于兼容末端工具；不能仅凭引脚数量认定夹爪协议兼容 |
| 底座 I/O | DI×16、DO×16、24V×4、GND×4 | 可以扩展按钮、指示灯等 |
| 控制软件 | DobotStudio Pro | 用于点动、示教、坐标设置、状态检查与模式切换 |

官方介绍包含拖拽示教和轨迹回放。实际使用方式以你的固件、软件和用户手册为准。

**型号辨别：**网上的 `Magician_ROS`、旧四轴 Magician 串口教程，以及 MG400/M1Pro 的四轴接口不是 E6 的直接开发入口。

### Python SDK 的版本陷阱

本次发现同一个官方仓库存在两套结构：

| 分支 | 本次核实提交 | 接口形态 |
|---|---|---|
| `main` | `82bce656c6e1a1c71599901baa93ed45bb50963d` | 单文件 `dobot_api.py`，含 `DobotApiDashboard`、`DobotApiFeedBack` |
| 默认分支 `feature/v4-optimization` | `55ec1ec82201aaf2e6d54aa47b6272bbaa14c815` | 包结构 `dobot_sdk`，入口 `DobotRobot`，按 `robot_control`、`motion` 等模块组织 |

两套教程中的 import、参数形式、数据结构不能混用。新默认分支 README 明确包含 E6，但 API 文档概述只列 CR3/CR5/CR10，且 Python 版本描述也有差异；这是文档一致性问题，不能据此替代固件兼容性核实。

旧 `main` README 的克隆命令还引用了不同仓库名。后续应从上表已确认的实际仓库与固定提交获取代码，不盲抄 README 的所有命令。

新默认分支随附 V4.6.6 接口 PDF；独立协议仓库当前提供 V4.5.1 PDF。**协议文档版本、SDK 版本、机器人固件版本和上位机软件版本是四件事。**

### 已确认的关键接口

| 能力 | 接口/通道 | 注意点 |
|---|---|---|
| 获取状态 | `RobotMode`、`GetAngle`、`GetPose` | 从只读查询开始；检查返回错误码，不能只提取数字 |
| 关节/直线运动 | `MovJ`、`MovL` | 区分目标空间、工具坐标系与用户坐标系 |
| 连续目标跟随 | `ServoJ`、`ServoP` | 文档提供接口；实际稳定频率、延迟与固件行为需实测 |
| 拖拽模式 | `StartDrag`、`StopDrag` | 旧 `main` 接口中可见；结合实机模式与官方操作流程使用 |
| 停止队列 | `Stop` | 软件停止不能替代硬件急停；断网时软件命令可能无法送达 |
| 状态反馈 | TCP 30004 | 用于采集与状态监测；按匹配版本解包 |
| 命令 | TCP 29999 | V4 资料中的主要命令接口 |

SDK 原生关节角/姿态角使用度、位置使用毫米。ROS 常用弧度/米，数据集可以自行选择约定，但必须在边界明确转换。

官方 README 示例 IP 并不一致：Python 新分支写 `192.168.1.100`，ROS 2 写 `192.168.5.1`。应使用现有官方软件显示的真实地址，并按实际子网掩码配置网络；“都以 192.168 开头”不足以保证同一子网。

不要把反馈报文频率、ROS 发布频率、策略推理频率和命令执行频率当成同一个指标。当前 ROS 2 README 标注 `/joint_states_robot` 为 10 Hz，这不是 E6 控制器全部能力的上限。

SDK 出现力控、传送带等通用接口也不等于这台 E6 已具备相应传感器或授权。本次未确认 E6 开放关节力矩控制，因此不以力矩控制/阻抗控制为初期路线。

## 4. ROS、运动规划与仿真

| 资源 | 核实结果 |
|---|---|
| [DOBOT_6Axis_ROS2_V4](https://github.com/Dobot-Arm/DOBOT_6Axis_ROS2_V4) | 官方明确支持 E6/ME6；README 推荐 Ubuntu 22.04、ROS 2 Humble |
| [ROS 2 中文说明](https://github.com/Dobot-Arm/DOBOT_6Axis_ROS2_V4/blob/main/README_ZH.md) | 包含网络、RViz、MoveIt、Gazebo 与实机启动方式 |
| [me6_moveit](https://github.com/Dobot-Arm/DOBOT_6Axis_ROS2_V4/tree/main/me6_moveit) | E6 的 MoveIt 配置目录 |
| [cra_description](https://github.com/Dobot-Arm/DOBOT_6Axis_ROS2_V4/tree/main/cra_description) | 各型号 URDF/XACRO 与网格资源；选择 E6 对应模型 |
| [TCP-IP-ROS-6AXis](https://github.com/Dobot-Arm/TCP-IP-ROS-6AXis) | 官方 ROS 仓库描述包含 CRA/CR/E6/Nova；旧 ROS 路线仅在兼容已有项目时考虑 |
| MuJoCo / Isaac Sim | 通用研究工具；本次没有确认官方提供可直接运行的 E6 完整任务环境 |

ROS 2 对调试坐标变换、看模型和做规划有价值，但 Python TCP/IP 直接控制无需先装 ROS。URDF 能显示或规划运动，也不代表已经有准确的碰撞、摩擦、接触和执行器动力学模型。

当前 ROS 2 README 的克隆示例指定 `feature/v4-optimization`，本次归档的 `main` 提交为 `ec201c40d5db63185a3593ec9c39f80fe25aa527`。实施时同样要固定分支/提交，并核对 launch 文件和文档一致。

| [DobotCameraCalibrate](https://github.com/Dobot-Arm/DobotCameraCalibrate) | 官方账号下的相机标定工具 | 后续可检查，具体相机与 E6 流程适配尚未核实 |

本次针对 E6+LeRobot 的公开检索没有验证出成熟的一键适配方案；这不证明社区不存在其他实现。第三方代码在核对型号、协议、动作语义、维护状态并做离线检查后才值得采用。

## 7. 仍需补齐的信息

1. 你的控制器固件、DobotStudio Pro 版本和实际 IP。
2. 对应硬件修订版的安装/负载/接线图，以及 J4/J5 抱闸选配与维修判定资料。
3. 在该固件上实测反馈与命令延迟、连续跟随行为、停止与断线行为。
4. 当前电脑已检测为 Windows 11 专业版、RTX 5070 Ti 约 16 GB；仍需确认最终训练是否用此电脑，以及 Linux/远程 GPU 的安排。
5. 后续若采购附件，再核实夹爪重量、行程、安装孔位、电气与控制协议。
