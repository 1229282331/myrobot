## 方法、依据与限制

脚本直接使用 Python 标准库 socket；不导入或执行厂商 SDK，不调用带自动使能逻辑的示例。29999 固定查询列表为 `RobotMode()`、`GetAngle()`、`GetPose()`、`GetErrorID()`；本次第一项受到控制模式限制，后续三项未发送。关节与 TCP 数值来自 30004。

反馈布局来自官方 [dobot_api.py 固定提交](https://github.com/Dobot-Arm/TCP-IP-Python-V4/blob/82bce656c6e1a1c71599901baa93ed45bb50963d/dobot_api.py)，标记校验来自同提交的 [DobotDemo.py](https://github.com/Dobot-Arm/TCP-IP-Python-V4/blob/82bce656c6e1a1c71599901baa93ed45bb50963d/DobotDemo.py)。已静态核对选用字段偏移、1440 字节长度和 `0x123456789abcdef` 标记，检查数值有限性。控制器固件版本尚未确认，不能据此宣称 SDK 全部接口兼容。

归档的新 SDK API Markdown 将 RobotMode=4 列为“远程”，与上述官方源码枚举冲突。本次采用源码中的 `ROBOT_MODE_DISABLED`，且 EnableStatus=0 与之相符。RobotMode 与 TCP/IP 控制模式是不同概念。

首次脚本只等分号结束的标准回复，最终超时；第二次保留了超时前收到的 24 字节，明确识别控制模式提示。之后脚本已支持这类不带分号的回复，并用捕获内容离线验证，不必等待超时。记录保留原始结果，不改写为成功。

## 控制模式说明（2026-09-19 补充）

“未使能”描述机械臂运行状态；“TCP/IP 模式”决定是否接受二次开发命令。当前只确认未使能且不在 TCP/IP 模式，不能由此确定 GUI 一定显示“在线模式”。持续反馈已可读取，因此仅接收状态不必为此切换模式。

GUI 入口参考[梅卡曼德的 Pro v4.x 集成说明](https://docs.mech-mind.net/zh/robot-integration/latest/full-control/dobot-cra-setup-instructions.html)：连接控制器后，点击“设备模式”旁当前模式，选择“TCP模式”并确定，成功后显示“TCP/IP二次开发”。该文档示例使用 Pro 4.5 / 控制器 4.5.1，且标明仅在仿真器中测试；用作界面入口参考，不能视为用户 E6 当前版本的实测证明。

官方 `dobot_TCP_IP_V4.6.6_20260410_cn.pdf` 第 4 页修订记录说明 V4.6.0 新增 `RequestControl()`；第 8～9 页说明它请求切换至 TCP 模式，允许未上电或下使能（非暂停、非松抱闸）等规定场景，不允许使能空闲、拖拽、运动、暂停或开启手自动模式等场景。由此修正此前“必须在 Pro 中切换”的表述：匹配版本也可以通过协议申请切换，实际支持需核对用户控制器固件。

切换控制模式、使能、下发运动是不同操作。当前只读脚本不含 `RequestControl()`，本次解释也没有向机器人发送任何新指令或切换模式。
