核查日期：2026-09-20。本轮仅阅读照片、官方手册和开发板资料，没有连接或控制任何硬件。

同日 USB 补充核查：静态分析官方 REF-CLI v1.0.3 后，已确认本体 Type-C 上位机使用 PyUSB/USB Bulk/Fibre 远程对象协议，能直接设置中间开度，并非外置 USB-CAN 通道。发现非 Windows 分支，RDK/Linux 有移植路径但尚未实测；可优先台架验证原生 USB，以下 CAN 架构保留为明确协议方案。详见 [原生 Type-C 核查](OmniPicker_原生TypeC_USB核查_2026-09-20.md)。

## 推荐系统

```text
主电脑（策略、训练/推理、操作界面）
    │ 家庭局域网 / Wi-Fi
    ├── E6，192.168.1.4：现有 TCP 机械臂接口
    └── RDK X5，放在底座旁
           ├── 板载 CAN 接口 ─────┐
           └── USB 3.0 → 未来相机  │
                                  │ 本地分线端子/小盒
独立 24V DC 电源 ────────────────┤
                                  │ 一根柔性六芯复合线沿臂布置
                                  └── OmniPicker

机械连接：E6 法兰 → 定制转接盘 → OmniPicker 原后端盖/夹爪
```

夹爪与 E6 由软件协调。E6 的六针末端口为 24V/GND/2DI/2DO，不是 CAN 口，本方案不使用它连接夹爪。CAN、电源可合为一根物理线束，但仍是独立芯线。相机 USB 是另一条数据链路，不会通过这根六芯线；可在机械布线时一起管理。

RDK X5 不放到腕部，避免增加负载。外部随动线仍限制 J6 连续旋转；固定走线、关节服务环和应力释放只能管理有限转角，不能当作无限旋转滑环。

## 供电与六芯线序

官方第 2.4 节标称工作电压 24V DC；第 5.1 节将 1/2 针定义为电源输入、5/6 针为地。按照片判断的 **20 PCBA**，本方案接线如下：

| OmniPicker 针号（不是按照片左右数） | 信号 | 在底座旁接到 |
|---|---|---|
| 1、2 | VIN | 独立 24V 电源正极，保留两芯并联 |
| 3 | CAN_H | RDK X5 的 CAN_H |
| 4 | CAN_L | RDK X5 的 CAN_L |
| 5、6 | GND | 电源负极，保留两芯并联；同一参考地点接 RDK CAN 接口的 GND |

电机回流通过电源负极线返回电源，不串过 RDK 的细地线。RDK 自己仍使用规定的 5V 供电，**24V 不接 RDK CAN/GPIO/USB**。若未来换隔离 CAN 接口，按该接口的隔离侧接地说明重新接线。

30 PCBA 则是 3=CAN_L、4=CAN_H。到货后按 SN、板型和原线连续性确认，不能仅凭线色或“六针”外形施工。若线缆已经把双 VIN/双 GND 合并成四根散尾，先查清原厂合并方式与载流能力。

### 电源怎么准备

- 优先向供货方确认并取得这台实物适用的 **稳压 24V DC 电源与额定/峰值电流规格**，或使用可限流台式直流电源完成台架验收。
- 本轮官方手册未找到额定/峰值电流，不能把 24V 1A/2A/3A 中某档写成已经验证的适配器规格。端子、线径、保险丝和限流值要跟随实物电流要求选择。
- 使用有绝缘外壳、短路保护的电源/端子；预留独立夹爪电源切断手段。E6 急停并不天然切断这个外置夹爪电源。
- E6 末端取电是候选方案：两侧电压匹配，且电源针脚独立于 PNP 数字输出；是否可实际使用，仍需匹配 E6 腕部电源针脚的连续/峰值电流与夹爪启动、夹紧峰值电流。
- Type-C 已确认用于 REF-CLI USB 数据/控制；未确认其单线电机供电、PD 或 VBUS 路径。不能断言所有 Type-C 都不能供电，也不能把只插 USB 作为本机运行方案。主电源先按六针 24V 设计。

### 补充：能否直接使用 E6 腕部电源

2026-09-20 核查：E6 V1.4 手册第 6.2 节定义末端针 1 为 24V 输出、针 6 为 GND，其余四针为 PNP DI/DO。第 6.1.3 节在底座接口说明中写明单路 DO 最大 500mA、总电流负载能力 2A；附录及[官方产品页](https://www.dobot-robots.com/products/education/magician-e6.html)概括为 `24V, Max 2A, Max 0.5A for each channel`。这些表述没有单独给出腕部 24V 电源针的连续/短时峰值能力及其与底座输出的共享关系，不能把 2A 直接认定为腕部可独享，也不能把 DO 的 0.5A 限值直接套到电源针上。

OmniPicker 手册标称 24V DC，但本轮未查到可靠的额定输入、启动和夹紧峰值电流。因此结论为**电压与拓扑可行，供电容量尚未确认，未做实机验证**。

若后续确认容量、接头和线束满足要求，可采用以下功能连接（并非即刻上电指令）：

```text
E6 末端 24V / GND ── 短转接线 ── OmniPicker 六芯线 VIN / GND
RDK X5 USB Host ── 沿臂 USB 数据线 ── OmniPicker 本体 Type-C
```

电源对应 E6 针 1 → 夹爪 VIN 针 1/2，E6 针 6 → 夹爪 GND 针 5/6；实际按官方编号、插合视角及原线连续性核线，不能凭线色或六针外形直接插接。E6 DI/DO 不参与夹爪供电或控制，夹爪 CAN 两芯在此 USB 方案中不用并分别绝缘。短线取电可减少一条从底座沿臂延伸的电源线，USB 仍需沿臂管理。不得将 E6 的 24V 输出与外置 24V 电源直接并联。

所缺规格可明确询问：越疆确认“E6 末端六针口 1/6 针连续电流、允许峰值及持续时间、与底座是否共用 2A 预算”；智元/供货方确认“该台 OmniPicker 的额定输入电流、上电归零及最大夹紧峰值电流”。首次接电仍需预留自动闭合空间，官方默认上电会使能并闭合归零。

## RDK X5 的 CAN 接法与软件

RDK 官方 CAN 文档确认：板载 TCAN4550，已集成控制器和物理收发器，CAN 连接器为 **SH1.0 1×3P**，信号为 H、L、GND，并有 120Ω 终端电阻开关。只需匹配接口的三芯插线，不必另购 CAN 收发器或 USB-CAN；针脚方向以 RDK 丝印/官方图为准。

首轮采用 **经典 CAN 1 Mbps，采样点 80%**。OmniPicker 手册支持此模式；RDK 当前使用文档列出的 CAN-FD 支持值为 2 Mbps，不直接照抄夹爪的 1M/5M CAN-FD 配置。

- 两节点总线：RDK 端启用 120Ω 终端，OmniPicker 默认已有 120Ω；买来的二手板需核对，避免重复添加。所有设备断电后，两端均有 120Ω 时 H/L 间通常约 60Ω，可作辅助检查，不代表线序/供电全部正确。
- CAN_H/CAN_L 使用双绞线，电源芯线按电流和压降选择；长度按底座至腕部实际活动路径测量。
- 20 版默认焊接配置是 CAN，保留即可；若实物已改 RS485，先明确现状，不按照片盲改焊点。
- 软件使用 Linux SocketCAN，可用 Python `python-can` 或标准库 SocketCAN 发送手册定义的帧，不依赖 Windows 上位机长期运行。
- 官方 CAN 协议要求固件 ≥3.3.0；先用 REF-CLI 查看实物固件与 `can_node_id`。手册中的 ID=8 是例子，不是用户实物的保证值。升级只在版本确实需要且匹配实物时进行。

在 RDK 上配置 CAN 端口的参考命令（仅供后续配置，**本轮未执行**）：

```bash
sudo ip link set can0 down
sudo ip link set can0 type can bitrate 1000000 sample-point 0.8 fd off loopback off
sudo ip link set can0 up
ip -details -statistics link show can0
candump can0
```

先确认系统确实枚举 `can0`。这些命令配置/读取 RDK 总线，未给出夹爪动作帧。CAN 模块正常工作会参与 ACK，不等于电气上的纯监听模式。

**反馈不是默认持续广播：**手册第 6.3.2 节说上电使能成功后，每收到控制命令立即上报一帧。因此只运行 `candump` 没数据，不一定是线没接好；不能为了“查询”随便发送动作帧。到货测试中需将“受控下发目标”和“读回响应”作为一对验证，并区分本机发送帧与夹爪响应帧。

协议可设定位置、速度、扭矩、加减速，并返回实际位置/速度/扭矩及状态、故障码。位置为 0–255 的离散数值，可逐周期更新，符合可变开度控制需求；不能承诺无限分辨率、特定控制频率或直接将其当作指尖毫米。Force 字段说明是扭矩，不是指尖力传感器的牛顿值。

当前官方手册指向 `agillink_omnihand_sdk` 的故障排查页，但本轮该仓库 README 未列旧 OmniPicker 型号。不能仅凭链接就承诺 SDK/ROS2 接口已兼容这台 20 板；首轮采用清楚公开的 OmniPicker CAN 协议。

## 到货使用顺序

1. **断电验货：**记录铭牌/SN、完整重量、后盖/螺钉/夹指/软垫、原线两端；核对 20 板模式与针号。
2. **独立台架首次通电：**固定夹爪本体，留足自动闭合空间。手册第 6.1/6.2 明确默认上电自动使能并闭合归零；“只接电、不发命令”也可能发生动作。接线/插拔安排在断电状态，避免手持夹爪通电。
3. **Windows + USB-C 验收：**六针电源就绪，官方 REF-CLI 读取设备信息/固件/CAN ID。再在明确的动作测试中试几个中间开度并读反馈；不要一上来复制手册全速全扭矩示例或执行校准/刷固件。
4. **RDK CAN 台架验证：**保留同一 24V 电源，换为 CAN 工作通道，验证目标/真实反馈、方向、超时、掉线和停止策略。关闭会同时发控制命令的其他上位机程序。
5. **完成转接盘安装：**量实物孔位并加工，核对螺钉长度、安装顺序、出线口和线缆服务环；称量整套末端并建立工具坐标/重心。
6. **再与 E6 联调：**沿用 E6 TCP 通信，RDK 在本地管理夹爪。低速检查运动范围与线缆，建立同步时间戳、命令过期丢弃、断网后不续跑旧命令等机制。

当前 E6 历史实测存在下使能 J4/J5 保持问题，尚未解决。新增约数百克末端前应先排查；这不阻碍夹爪先独立台架验收。本轮没有对机械臂使能、运动、IO 写入或更改参数。

E6 标称 750g 是整套工具与物体共同占用，且 V1.4 第 5.5 节要求按合成质心偏心距离降额，超过 60mm 后上限下降。实际夹爪重量未确认，不以 PCBA20 推断 360g。安装盘、相机、线缆与物体一并计算，不能只用 750 减去夹爪重量得出全姿态抓取保证。
