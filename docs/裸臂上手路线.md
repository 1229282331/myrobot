# 不买夹爪和相机，先把 E6 玩起来

你已经能用官方软件控制机械臂，接下来可以直接从程序控制和状态记录开始。没有夹爪影响抓取，没有相机影响视觉反馈，但都不阻止运动学和状态输入的学习实验。

## 1. 现在可以做什么

| 项目 | 额外设备 | 可以学到什么 |
|---|---|---|
| 实时显示六个关节角和末端坐标 | 无 | 通信、反馈解析、坐标约定 |
| 程序控制一个关节做小范围往返 | 无 | 目标与实测位置、速度、完成状态 |
| 末端在空中画线、圆、数字和字母 | 无 | 笛卡尔轨迹、逆运动学、姿态约束 |
| 录制示教动作并回放 | 无；通过官方允许的示教方式 | 时间序列、插值、动作同步 |
| 键盘或手柄控制 | 键盘已有；手柄可选 | 遥操作、限位、动作采集 |
| RViz 中同步显示实机 | 无；需软件环境 | URDF、关节状态、坐标变换 |
| 学习从不同初始姿态到达指定目标 | 无 | 状态输入的行为克隆、目标条件、泛化评估 |
| 毛笔/笔绘图 | 后续需可靠的轻量夹具 | 工具坐标与接触控制；空中轨迹稳定后再做 |

没有视觉或其他外部传感器时，机器人无法自动知道任意物体被移动到了哪里。可以从人工指定坐标、固定目标或已知任务条件入手。空中画圈与固定轨迹回放属于控制实验；训练模型后在新初始状态/新目标上评估，才构成相应的学习实验。

## 2. 推荐的第一个项目：E6 状态记录与轨迹回放

最终做成一个小工具：显示机械臂状态 → 录制 → 查看轨迹 → 慢速回放 → 比较目标与实际轨迹。

### 第一步：确定连接配置，只读取状态

从官方软件取得实际 IP、控制器固件版本、软件版本，选定匹配 SDK 的分支和提交。官方软件与 TCP/IP 控制之间按官方流程切换，不同时让两个程序争用运动控制。

只读程序显示：

- `RobotMode` 与错误信息。
- 六个关节角。
- 末端位姿，以及使用的 Tool/User 坐标系编号。
- 本机单调时钟时间戳、反馈到达时间和状态新鲜度。

验收：静止时读数合理，官方点动后能看见对应关节变化，断开连接能明确报错。连接动作本身不应自动使能、清错或运动；有些官方“连接示例”同时包含这些动作，不能当作只读脚本原样运行。

### 第二步：最小运动闭环

先从当前实测姿态附近的小范围目标开始。给出一个关节目标，确认接收成功，并通过持续反馈判断到位；避免一上来执行教程中硬编码的空间点位。

把关节限位、每步最大变化、速度上限、反馈过期处理集中在同一层。初次实机运动前固定底座、确认清空运动区域和硬件急停可用，这是验证动作必需的现场条件。

验收：可以区分“命令发送成功”“控制器接收成功”和“机械臂实际到位”；停止操作确实停止运动。

### 第三步：记录数据

优先使用持续反馈通道记录。初期可把数据集采样目标定为 10–20 Hz 这一保守范围，但它是实验起点，最终依据实际反馈、命令延迟和任务需求确定，不是厂商保证的频率。

每条记录至少包含：

| 字段 | 含义 |
|---|---|
| `episode_id`, `frame_index` | 哪一段任务、哪一帧 |
| `timestamp_monotonic` | 单调时间戳，避免系统时间校准造成倒退 |
| `q_measured[6]` | 实际六关节角 |
| `tcp_measured[6]` | 实际末端位姿，注明单位和姿态表示 |
| `q_commanded[6]` | 本帧发出的关节目标；没有下发时记录为空，而不是伪造 |
| `robot_mode`, `error` | 机器人模式与异常 |
| `task`, `success` | 任务说明和结果 |

每个数据集额外保存固件/SDK 版本、关节顺序、坐标系、单位、采样设置、负载与工具配置。当前没有相机或夹爪，对应字段应省略或明确标记不存在。

官方拖拽示教时可记录实际姿态，但实际轨迹不是操作者下发的电机目标。若之后用未来关节位置构造模仿学习标签，要明确记录时间偏移和标签定义。

验收：时间戳递增，六关节顺序固定，缺失/异常帧可识别，能在图上看出完整动作。首先保存中立原始数据，如 JSONL/NPZ；确认格式后再导出目标框架的数据集。

### 第四步：回放与误差分析

先离线检查轨迹的角度跳变、越界和速度。回放要有明确的起始位姿过渡，不能直接跳到录制第一帧。按已验证的控制方式做插值和慢速执行，比较实际位置与目标位置。

跨越 ±180° 或多圈关节位置时，不能不检查就进行简单线性插值或随意归一化。过期动作和断线前排队的动作不能在重连后自动继续执行。

验收：同一段轨迹能重复执行；位置误差、运行时长和异常次数都有记录。

## 3. 第一个学习任务：目标条件的到达动作

建议先训练一个小型状态输入模型，使用 CPU 或普通 GPU 即可开始开发，实际训练耗时依模型规模决定。

一个明确的任务定义：

- 输入：当前六关节角、目标六关节角，必要时加入速度或短历史。
- 输出：下一小步关节目标或关节增量，二选一并固定语义。
- 数据：在安全范围内从多个初始状态到多个目标的示范轨迹。
- 基线：普通插值/传统控制算法。
- 评估：保留未参与训练的初始状态与目标，比较成功率、终点误差、路径长度、执行时间和越界次数。

数据量先以能检验采集流程的小批量开始，再根据验证集误差扩大；不承诺“几十条数据一定成功”。划分训练/验证集时按完整 episode 和目标组合划分，避免相邻帧泄漏造成虚假的高准确率。

这个任务可用于理解行为克隆，但到达已知关节目标本来就能被传统控制很好地解决。学习模型的意义是练通数据—训练—部署过程，不能将它包装成 π0.5 的视觉泛化复现。

## 4. 后续按兴趣扩展

1. **空间轨迹与运动学：**研究姿态约束、避开奇异位形和关节边界。
2. **遥操作采集：**键盘/手柄能启动流程；更复杂任务再考虑主从臂或其他遥操作器。
3. **ROS 2：**加入 RViz 和 MoveIt，先查看/规划，再执行。
4. **视觉任务：**先加一台固定 RGB 相机，做彩色目标指向或到达目标上方；不一定立刻加夹爪。
5. **操作任务：**需要抓取时再选夹爪；指向、推物和抓取对应的硬件要求不同。

## 5. 当前需要的信息

下一步只读连接需要：**机械臂 IP、控制器固件版本、官方软件名称与版本**。电脑配置影响后面的环境选择和模型训练，可以稍后补齐。
