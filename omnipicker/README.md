## 启动

本机已创建 **Conda `omnipicker`，Python 3.11.16**，依赖安装完毕。双击本目录 **`launch.cmd`** 即可启动。启动默认选择模拟设备，**不会自动连接、使能、改参或发开度**。

也可从 PowerShell 启动：

```powershell
cd C:\vscode_files\robot\omnipicker
conda run --no-capture-output -n omnipicker python -m studio
```

在新机器安装（先安装 Conda；不要使用 base 开发）：

```powershell
cd C:\vscode_files\robot\omnipicker
conda env create -f environment.yml
conda run -n omnipicker python -m pytest -q
.\launch.cmd
```

运行/测试均使用本环境。`requirements.txt` 固定 Python 依赖（含间接依赖），`environment.yml` 固定 Python 版本。应用按源码目录启动，无需 ROS、REF-CLI 子进程或安装本项目为 wheel。Qt 默认使用 D3D11。

## 操作

1. 选择“模拟设备”或“真实设备 · USB”，点击连接。真实设备默认 USB SN `20773954464D`。设备首次连接显示“使能状态未知”，不读取不存在的状态属性。
2. 若要调参，先下使能，再滚动右栏打开“运动参数”，选档或编辑六项数值，“应用并核对”。原值保存为本次连接基准，参数不能大于基准，不写 Flash。
3. 点击使能。开度输入按 Enter / 离开输入框提交；预设直接提交；拖动滑块实时提交。未使能时只编辑目标；连接后的三维仍跟随回传位置。输入步进 0.1% 是指令分辨率，不是实机精度。
4. “开始往返”执行 A → B → A，按次数重复；默认 15% ↔ 35%、每段 6 秒、1 次。最多 100 次。运行期间手动目标入口被锁定；完成后仍使能并保持末次目标。
5. 顶部“停止（下使能）”或 Escape 清除待发目标和剩余测试，请求下使能。**这不是硬件急停**；通信失效时会明确报告“停止未确认”。
6. 关闭 / 断开时，如使能状态未知或可能使能，会提供下使能后退出、保持使能退出、取消。下使能退出收到确认后恢复临时参数；保持使能退出不写状态和参数。

10% / 25% / 50% / 100% 档位将前五项乘以连接时基准；电流上限取 `min(原值, 1 A)`。完整恢复请使用“恢复原参数”。速度/加减速数值沿用设备原生单位，未映射为夹指 mm/s。

模型支持鼠标拖动旋转、滚轮缩放、双击或按钮复位。底部面板可折叠，右栏可滚动；Ctrl+Shift+S 或“截图”保存当前界面到 `logs/`。

## 反馈语义与异常

- **编辑目标**：操作者当前选值，同时驱动目标动画。
- **最近已确认指令**：开度参数写入及函数触发收到 USB/Fibre 应答，不等于实际到位。
- **故障码**：约 5 Hz 实读；RTT 是最近一笔 USB 事务耗时。
- **使能 / 下使能请求已确认**：本程序发送的请求返回 True；已核验的固件 330、335 均没有实时使能状态属性。
- **回传位置 / 速度**：335、debug_flag=56下读取CDC第三/第二列，显示归一化%和%/s；位置文本量化1个百分点。不是毫米开度或mm/s。第1列仅作为未核实单位的原始量展示。三维常驻注明“名义联动 · 不含受力指节形变”，姿态输入来自回传开度；断开后才切到明确标识的目标预览。
- 335的CDC不可用时不允许使能/新运动；超过300ms无新数据后显示“—”。若本程序已使能，则取消动作并尝试下使能；只读连接状态未知时不自动写状态。恢复须重连，不自动续跑。

写操作不重试；故障、超时取消剩余动作并锁定运动，尝试一次下使能。停止请求自身失败不再次发送同一请求。重连不自动使能或续跑。异常断连后，同一进程保留原限幅基准，重新连接同一设备后可下使能并恢复；程序被强制杀死 / 电脑断电时不能保证下使能或恢复参数，需重新检查 RAM 配置。

本固件可能拒绝重复的状态转换。程序仅在本次会话已确认下使能、且之后没有可能使能的请求时跳过重复下使能；初次连接状态未知时，不把 False 猜成“已经下使能”。此时会显示“停止未确认”，应核对设备状态后再进行明确的使能/下使能操作。

模拟设备提供“模拟故障”“模拟超时”“模拟反馈中断”，只作用于内存模拟器。不要靠拔正在运动的设备做异常测试。模拟器不产生实物运动或真实位置观测。

## USB 与兼容范围

本机已验证：VID/PID `1001:03EF`、MI_02 / interface 2 的 `REF Interface` 为 **WinUSB**；另一 CDC / usbser接口由同一USB序列号自动匹配（本机COM29），用于只读反馈接收。打开前DTR/RTS=False，115200/8N1，不发CDC应用字节、不改debug_flag。底层不执行USB reset、set_configuration或内核驱动分离。CDC格式目前仅对335、debug_flag=56开放；330保留原Fibre控制，不提供未经验证的CDC观测。

连接下载设备 JSON，校验固件 `330` 或 `335`、device_type `1` 及各自完整接口定义，再开放写操作。所有端点编号从本次设备定义解析，两个版本不共用编号。未知版本或定义不匹配保持只读（若身份 / 故障属性本身无法读取，会报告连接失败）。新机器须先为正确的 vendor 接口安装 WinUSB，不要覆盖 CDC 或其他设备驱动。

只读诊断（先在 GUI 中断开 USB，避免端口竞争）：

```powershell
conda run -n omnipicker python tools/read_only_probe.py
```

## 目录与证据

| 目录 / 文件 | 用途 |
|---|---|
| `studio/protocol.py` | Fibre 编码、CRC、单次事务和 USB 传输 |
| `studio/device.py` | 原生设备接口、能力校验、模拟设备 |
| `studio/control.py` | 单线程控制状态机、最新目标邮箱、停止与退出 |
| `studio/bridge.py` | QThread 与 QML 桥接、日志 |
| `studio/feedback.py` / `recording.py` | CDC只读接收、明确模拟反馈、后台有界记录队列 |
| `tools/export_observations.py` | 离线导出CSV，按同一连接中的主机时间关联确认目标 |
| `studio/model.py` / `scene.py` | URDF 几何联动、STL 直接加载、Qt 几何 |
| `qml/` | 深色桌面界面 |
| `assets/official/source.json` | 官方模型 URL 与下载 SHA-256 |
| `assets/schema-fw330.json` / `assets/schema-fw335.json` | 本台设备升级前后原始 JSON 接口兼容基线 |
| `tests/` | 离线协议、控制、模型及 QML 初始化测试 |
| `docs/` | 模型说明、实测验收与关键截图 |
| `logs/` | 每次运行 JSONL、Qt 日志、截图；Git 忽略 |

日志的 `record_type=log` 为动作/事件，`telemetry` 为故障轮询，`observation` 为逐条原始CDC/模拟观测。保留主机单调时间、运行ID、连接ID、固件和模拟标记；目标单位为百分比，观测位置为0–1、速度为fraction/s，二者分开。`enable_request`只描述请求结果。`host_sequence`为本程序解析计数，不是设备序号。查看 [采集字段、失效处理和CSV导出](docs/CDC反馈接入与采集说明_2026-09-27.md)。

首版没有固件升级、校准、Flash 保存、夹持力控制或 E6 联动。
