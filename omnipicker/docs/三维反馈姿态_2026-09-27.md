# Studio 0.2.1：三维跟随回传位置

用户反馈：夹持物体时回传开度与目标不同，而三维仍随目标变化。0.2.1将连接后的三维输入改为有效的`feedbackPosition`，右侧目标输入、控制发送、指令确认和采集字段保持各自语义。

## 显示行为

| 状态 | 三维显示 |
|---|---|
| 已连接，有效实机反馈 | “反馈驱动姿态”，模型按回传开度更新；例如目标35%、反馈15%，模型显示15% |
| 模拟设备，有效反馈 | “模拟反馈姿态”，使用模拟器动态位置，不使用目标回显 |
| 反馈中断、过期或无效 | 保留本次连接最后有效姿态并变暗，显示“反馈失效 · 姿态冻结”，主数值为“—”，末次回传标为非实时 |
| 新连接尚无有效反馈，包括不支持反馈的固件 | 隐藏模型，显示“等待位置反馈”，不借用上一连接的姿态 |
| 未连接 | 明确显示“目标预览 · 未连接”，允许离线查看目标姿态 |

反馈直接随现有约20Hz界面状态更新；移除了旧的160ms目标动画，不外推未来位置。原始CDC接收和采集仍保持原流程。几何允许的范围为0–100%，边界附近小幅超限只限制几何输入，原始反馈显示和日志不被改写。

**这仍是按回传开度驱动的名义联动模型。** 官方资料缺少开度到关节角的标定映射，当前反馈也没有逐指节角度。因此不显示实际毫米开口，不声称受力包络形态与实物逐节一致；界面常驻“名义联动 · 不含受力指节形变”。整体回传位置与已确认目标也不能单独证明物体已抓稳。

## 验证与证据

- Conda `omnipicker`环境全套82项测试通过，含9项新增显示/Qt测试。覆盖目标与回传不一致、修改目标不改变反馈模型、回传更新确实改变网格变换、反馈失效冻结、重连不沿用旧姿态、非有限值、边界及模拟标识。
- Qt实际加载、渲染两个窗口尺寸1100×760/1440×900；150%与225%有效缩放通过。注入的显示测试数据明确标识为模拟，未接硬件。
- computer-use实际操作新版模拟器：连接后模型0%、目标15%；编辑35%后模型仍0%；模拟使能并下发35%后，观察到模型与反馈同步为2%，目标已为35%；随后反馈到35%。模拟反馈中断后模型冻结并变暗，主数值变为“—”，模拟下使能确认；最后正常关闭程序。
- 本轮仅修改显示、版本号和文档，未连接真实USB、未驱动夹爪、未改设备参数。用户报告的真实夹物现象是需求依据，本轮没有新增实机带载验证。

证据目录：`evidence/feedback_pose_20260927/`。包含全套与225%测试XML、模拟GUI日志、界面截图。GUI日志全部`simulated=true`。
