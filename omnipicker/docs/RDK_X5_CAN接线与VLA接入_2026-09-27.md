# OmniPicker 20 板 → RDK X5：CAN 接线与 VLA 接入

**同日后续实测：** 已验证同一Type-C上的“Fibre控制+CDC反馈”：15%→35%→15%低速动作中，位置列逐步达到三个目标，速度列积分与位移一致，2077条有效记录约100Hz。第一列物理单位仍未核实，位置文本量化为1个百分点。CAN接线方案仍有效，但不是VLA获得状态反馈的唯一候选；可先沿用现有USB做采集原型，见 [动作反馈与公开资料复核](USB_CDC动作反馈与公开资料复核_2026-09-27.md)。RDK上的USB/CDC尚未实测。

核查日期：2026-09-27。资料核查与工程方案；没有连接RDK、发送CAN帧或操作夹爪。本机USB已验证固件335、CAN节点ID=1；尚未进行CAN实机验证。以下板端针号针对普通RDK X5开发板，不能直接套用第三方载板。

## 对VLA的意义

OmniPicker本体USB/Fibre在固件330和335上都能下发开度并读故障，但本机实际接口定义未导出当前位置、速度、电流或使能状态。该限制来自设备接口，不是USB无法双向通信，也不是夹爪内部电机没有闭环。视觉策略仍可使用USB目标控制；若希望采集夹爪实际状态、区分运动/到位/堵转，推荐通过六针口使用公开CAN协议。

官方CAN反馈为故障码、状态、当前位置、速度及力矩。位置和指令均为0–255的8位值，归一化步长约0.392%；这是协议量化，不是实机定位精度。力矩字段不是指尖力传感器的牛顿读数，也不是独立手指关节角。不能把它称为无限精度或全部传感器反馈。

## 默认模式

官方英文手册§5.1/5.2明确：20 PCBA出厂通过焊接跳接电阻选择CAN/CAN-FD；保留默认CAN不需要焊改。30 PCBA改用拨码开关，而且CAN H/L针号与20版相反。

用户铭牌前缀X100620…指向20板，但尚未独立检查内部板型及焊点；二手设备可能被改动。335读回`rs485_mode=True`、`modbus_mode=True`属于串口配置，不能据此断言六针口物理跳接已改为RS485，更不应为了CAN随意修改它们。

## 准确针号及位置

RDK X5板载TCAN4550，已经包含CAN控制器和物理收发器。使用**独立的J18三针CAN插座**，不用40针GPIO，也不需要另外加收发器或USB-CAN。

J18位于40针排针末端与USB-A接口之间。官方照片中将40针排针放在上方、USB-A放在右侧时，三针从左到右为GND、L、H，即J18的3、2、1。反看线端插头会镜像，制作线束应以针号和导通测试为准。

官方公开原理图`RDK_X5_IO_CONN_PUBLIC_V1.1.pdf`的CAN区域已完成整页及局部渲染核对：J18-1=CANH，J18-2=CANL，J18-3=GND；4/5是插座固定焊脚的地，不是另两根线。J19是两针终端接入跳帽，闭合后把R196的120Ω跨接H/L。

| OmniPicker 20板六针口 | 信号 | 接到 |
|---|---|---|
| 3 | CAN_H | RDK X5 J18-1，H |
| 4 | CAN_L | RDK X5 J18-2，L |
| 5或6所在的公共地节点 | GND | RDK X5 J18-3；同时与夹爪24V电源负极共地 |
| 1、2 | VIN | 夹爪24V正极，不接RDK |
| 5、6 | 电源GND | 夹爪24V电源负极，承载电机回流 |

1/2与5/6列出的是官方同类针脚定义，不要求这次重做已验证的供电线。沿用用户当前24V供电，从原六芯线分出3、4及参考地即可；未使用的独立尾线绝缘。电机回流直接回电源负极，不让它串过J18的小地线。RDK按官方5V/5A Type-C方案独立供电，**J18没有24V供电针**。不要将E6电源和独立24V电源正极并联。

## 线材

最少新增一根**适配RDK X5 J18的SH1.0、3P、1.0mm间距母壳带线，另一端散线**。官方硬件表列板端料号`HDGC1002WV-S-3P`；购买时可将此料号与“RDK X5 CAN线”提供给商家确认配套，不以线色判断H/L/GND。它不是2.54mm杜邦插座，也不是夹爪的1.25mm六针插座。

夹爪端优先复用原装带锁扣六芯线，避免重新购买未经确认的1.25mm壳体。中间用绝缘接线端子连接；需要沿机械臂延长时，H/L用一对约120Ω特性阻抗的柔性CAN双绞线，另带参考地。电源线径按实际电流、长度和压降选择，不能让细CAN尾线承担电机供电。

J19准备匹配间距的两针短路帽，启用X5端120Ω；夹爪默认已有R47 120Ω，二手改装状态仍需核实。两节点只在两端各放一个120Ω，勿额外再并联一组。所有设备断电、无USB供电后量H/L间电阻，约60Ω是两端120Ω并联的辅助检查，不能替代线序和电压核验。

```text
主机：VLA推理/训练
          │ 以太网或Wi-Fi，带时间戳和命令有效期
          ▼
RDK X5：本地夹爪驱动与数据采集
  J18-1 H ─────────────── OmniPicker 3 H
  J18-2 L ─────────────── OmniPicker 4 L
  J18-3 GND ─┬────────── OmniPicker 电源GND节点
              └────────── 24V电源负极
                         24V电源正极 ── OmniPicker VIN
```

RDK放底座旁。CAN仍需一条沿臂线缆，网络连接只减少主电脑到机器人之间的拖线；相机USB另行连接RDK，不经CAN传输。若使用用户已选DaBai DCW，还须单独验证旧版OrbbecSDK、双流与时间戳。

## Linux驱动与软件步骤

RDK官方内核使用`ti,tcan4x5x` / `tcan4x5x-core.c`，应用层走SocketCAN。官方镜像正常启用驱动后应枚举`can0`；如果没有，先检查系统版本、设备树与驱动，不能用GPIO脚号代替CAN接口。

以下仅供后续在RDK执行，本轮没有执行；它们配置接口并接收数据，不包含夹爪动作帧：

```bash
sudo apt install can-utils
ip -brief link
sudo ip link set can0 down
sudo ip link set can0 type can bitrate 1000000 sample-point 0.8 fd off loopback off
sudo ip link set can0 up
ip -details -statistics link show can0
candump -tz can0
```

采用经典CAN 1Mbps、80%采样点，匹配OmniPicker协议。不要直接复制RDK通用示例的125kbps，也不要先用夹爪1M/5M的CAN-FD配置；经典CAN足以承载这些8字节帧。正常CAN接口参与ACK，不是电气纯监听。

应用可使用Python `python-can`的`socketcan`后端或Linux标准库CAN socket；不会使用RPi.GPIO脚号。在RDK上另建适合aarch64的独立Python环境，不能把Windows Conda目录原样复制过去；Windows已有Studio环境保持不变。

本台节点ID为1。按官方协议，下行与上行均使用该节点ID、DLC=8：

| 方向 | D0 | D1 | D2 | D3 | D4 | D5 | D6 | D7 |
|---|---|---|---|---|---|---|---|---|
| 控制 | 0 | 目标位置 | 速度限幅 | 力矩限幅 | 加速度 | 减速度 | 0 | 0 |
| 反馈 | 故障 | 状态 | 当前位置 | 当前速度 | 当前力矩 | 回显 | 回显 | 回显 |

位置指令`round(255 * q)`，q∈[0,1]；反馈可先用`pos/255`作为归一化观测，并保留原始整数。手册称速度/力矩等0–255对应各自最大值，物理单位和与RAM配置的关系仍待台架确认，不能直接当成mm/s、A或N。

状态枚举：0到位、1运动、2堵转、3物体掉落，以上是固件报告的状态，不等于独立传感器证实。反馈在上电使能成功后，每收到控制指令立即返回一帧；没有公开的独立只读查询帧。因此仅`candump`无报文不能判定断线，也不能把全零控制帧当只读查询（目标0会闭合）。收到状态帧不代表这次目标已经到位。

驱动须只允许一个命令发送者，排除本机发送回显；上下行ID相同，单按ID过滤不够。保留原始帧、收发时间、反馈年龄、指令与观测分别记录，并在超时/断线后丢弃过期目标。现场先低速15%–35%对照位置方向、状态、延迟和限幅；合格后才确定VLA动作频率。周期性发保持目标会触发反馈，但它仍然是运动控制命令，不能伪装成无副作用查询。

公开CAN八字节控制帧未定义独立使能/下使能或急停命令。本机`enable_on_boot=True`，上电可能闭合；不能把“停止发帧”当下使能，也不能承诺未验证的固件通信看门狗。停止与断网策略需结合已验证USB下使能或独立供电切断另行验收，接好CAN并不自动完成整套运行保护。

## 后续开发边界

现有Studio仍为USB与模拟器，尚未增加SocketCAN后端。本轮提供准确接线与开发路径，没有部署RDK驱动、安装依赖或做实机CAN验收。后续可沿用现有控制层的目标覆盖、限幅、过期丢弃及记录结构，新增CAN后端和真实反馈字段；将相机帧、E6关节、夹爪状态按明确时间基准记录，目标不能冒充观测。
