# Studio 0.2：CDC反馈接入与采集

2026-09-27。用户要求将已验证的USB反馈接入上位机和采集。所有开发、运行与测试均使用Conda `omnipicker`，新增正式运行依赖`pyserial==3.5`。

**后续更新0.2.1：** 三维已改为由回传位置驱动，见 [三维反馈姿态](三维反馈姿态_2026-09-27.md)。下文0.2的截图和只读采集数据保留为当时验收记录。

## 使用

双击`omnipicker/launch.cmd`。选择“真实设备 · USB”并连接，下方“设备反馈”将显示：

- **回传位置**：第三列×100，归一化百分比，文本分辨率为1个百分点。
- **回传速度**：第二列×100，单位为归一化`%/s`，张开为正、闭合为负；不是毫米/秒。
- **接收频率、数据年龄和最近10秒曲线**：青色为回传位置，虚线为本程序最近已确认的目标。未发指令时没有目标线。
- 第1列仅标作“单位未核实”，不冠以电流、牛顿或力矩单位。

0.2.1中三维模型由回传开度驱动，右侧编辑值仍表示目标；只有未连接时显示目标预览。模型未测量受力后的各指节姿态。连接不会使能、发开度、改debug_flag、清错、校准或写Flash。“测试与记录”默认折叠，可展开使用原来的有限次往返功能；停留仍按时间执行，不由位置相等推断实际到位。

![实机反馈与预览目标分开显示](evidence/cdc_integration_20260927/real-feedback-readonly.png)

上图为0.2历史截图：右侧35%是预览，回传位置为15%，最近已确认指令为“—”。当时模型仍显示目标，0.2.1已修正为跟随15%回传。这次界面验收没有向实机发送35%或其他开度。

## 接口和保护

- 原生Fibre仍由单一控制工作线程持有；CDC另有只读接收线程，记录文件由独立线程写入。界面不等待USB或磁盘操作。
- CDC按USB VID/PID `1001:03EF`和同一USB序列号找到唯一串口，不硬编码COM29、不扫描其他设备。
- 首版只对已验证的**完整schema、固件335、debug_flag=56**开放真实反馈。115200/8N1，打开前DTR/RTS=False，不发串口应用数据，不改设备参数；每秒通过Fibre复核debug_flag。
- 固件330保留原Fibre控制能力，显示CDC格式未验证，不伪造反馈。未知schema/固件保留原只读限制。
- 335没有可用CDC时，连接仍可查看Fibre故障，但使能/新运动入口关闭。启动2秒内没有合法行、格式变化、位置越出归一化合理范围、接收溢出或数据超过300ms未更新，都会使反馈失效。
- **若本程序已使能或正在运行测试**，反馈失效会清空待发目标、取消剩余动作、锁定控制并尝试一次下使能。停止失败仍显示“停止未确认”；不自动重试写操作。若只是只读连接且使能状态未知，不因接收失败擅自改变夹爪状态。
- 失效后数值变为“—”，旧曲线变暗。即使新数据回来，也必须重新连接才能恢复该会话的反馈有效性；不自动续跑旧动作。
- 模拟器提供“模拟反馈中断”，可以验证上述路径。模拟位置随时间变化，有明确“模拟反馈/非实机观测”标记。

## 日志与导出

连接期间自动记录到`logs/studio-日期时间-随机ID.jsonl`。文件名不会因同秒启动冲突覆盖。正常退出会关闭CDC/Fibre并排空记录队列；强制杀进程或断电不能保证尾部日志完整。

| record_type | 内容 |
|---|---|
| `observation` | 每条完整CSV原文、主机接收单调时间、位置fraction、速度fraction/s、第1列原始值、接收来源与格式有效性 |
| `log` | 连接、使能请求、目标确认、参数、停止、反馈异常等事件；目标确认另保留调用开始时刻 |
| `telemetry` | Fibre故障轮询、事务RTT、最近确认目标和使能请求结果 |

每条记录有`run_id`、`connection_id`、固件、序列号、软件版本及`simulated`。`connection_id`每次重连重新生成，用于隔离采集会话；尚未实现完整示教任务的episode划分和相机同步。`host_sequence`只是本程序成功解析行的编号，**不是设备帧序号，不能用于证明无线端/USB端未丢样本**。

接收不按界面刷新率降采样：本次实机约100Hz，界面约20Hz更新。接收队列和磁盘队列均有上限，溢出会明确报错。记录写入失败时，底栏显示错误；退出时尽可能写入`.incomplete.txt`标记。导出拒绝有失败标记、记录错误事件或不完整JSON的日志。

在`omnipicker`目录中，用专属环境离线导出：

```powershell
conda run -n omnipicker python tools/export_observations.py logs/你的会话.jsonl --output logs/你的会话.csv
```

导出禁止覆盖已有文件，不访问设备。保留全部观测行和`simulated`、`stream_accepted`；训练前应剔除模拟数据及未接受的流记录，并根据任务切分episode。它不会补帧、插值、把目标填成位置或自动同步相机。

CSV中位置仍为0–1的`position_fraction`，速度为`velocity_fraction_s`；`last_confirmed_target_percent`是0–100百分比。后者按**同一连接会话**中不晚于该行主机接收时间的指令确认关联，无此前确认则留空。它不表示该动作导致了该样本，也不是硬件采样时刻对齐。原始JSONL仍是完整证据，CSV用于分析便利。

## 验收

- **离线**：73项回归测试通过。新增覆盖严格三列解码、分块/CRLF、NaN/列变化/异常范围、精确设备匹配及无CDC发送、初始无反馈不改状态、反馈过期/错误/时间断层停止、恢复需重连、模拟动态、后台落盘、队列溢出和CSV按时间/连接关联。
- **界面**：computer-use实际连接模拟器、使能、35%预设、观察动态反馈、模拟反馈中断并确认数值失效/下使能、断开，再切真实设备。Qt检查1100×760和1440×900窗口，150%与225%有效缩放通过。
- **实机只读**：UI记录7249条CDC反馈，跨72.4197s，约100.083Hz；最长相邻主机接收间隔16.952ms。位置始终0.15、速度0；341次Fibre故障查询均0。没有解析/超时/记录错误。
- **前后配置**：02:33:18和02:38:26快照的62项属性及schema一致。真实连接日志的动作只有`connect`、`feedback_start`、`leave_keep`；没有使能、下使能、开度、改参或清错。退出选择保留原状态，关闭两个USB接口。
- **采集导出**：同一GUI运行包含4816条模拟观测和7249条真实观测，导出12065行，来源和连接ID分开；真实会话没有目标确认，因此对应目标列为空。

本次没有新增实机运动、带载或强行拔线测试。前一轮15%→35%→15%的实机动作对应关系见 [USB反馈实验](USB_CDC动作反馈与公开资料复核_2026-09-27.md)。位置不等于独立毫米测量，第1列单位未核实，100Hz仍是本次观察值，不作长期保证。
